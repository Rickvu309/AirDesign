# A test reads the page's engine metrics in thread time: `Performance.enable` over the DevTools protocol passes `{ timeDomain: "threadTicks" }`

lint: `no-wall-time-metrics`. In wall time a task's duration counts the time other processes hold the core, so a speed budget fails on a busy machine though the page did no more work. `no-wall-time-metrics.test.js` replays the wall-time reading `tests/browser/editor-speed.spec.ts` had until 2026-11-23. The same lint refuses `Date.now`, `performance.now` (also as `window.performance.now`), a pointer `timeStamp` (also as `event["timeStamp"]`), and a `longtask` or `long-animation-frame` entry type (also as a template literal) in `tests/browser/agent-paint.ts`, `tests/browser/drag-feel.ts`, `tests/browser/renderer-thread.ts`, `tests/browser/typed-letter.ts` and `tests/browser/editor-speed.spec.ts`. A `longtask` entry's duration is wall time: a renderer the scheduler paused for 105 ms inside one task read a 108 ms entry with 7.85 ms of thread work. `console.timeStamp`, which writes a marker into the trace and reads no clock, passes. Speed reads a task's traced `tdur` or DevTools engine metrics in thread time. Wall clocks include time spent waiting for the server and other processes. `no-wall-time-metrics.test.js` plants each one in each file.
