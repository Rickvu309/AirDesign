# Only a test imports test support

lint: `no-testing-import` on every non-test file under `apps/` and `packages/`. Test support is a `testing` folder or a `*.test.*` / `*.spec.*` file, and product code that reaches either hides in two blind spots at once: `ts-packwerk` allows every import inside one pack, and `pnpm dead-code` counts a `/testing/` path as test support, so the reference looks clean while it ships. The folder matches bare barrels too — `./testing`, `../testing`, `@/testing` all resolve to the folder's index — and re-exporting test support, straight or through a test file, still feeds product code, so the rule holds every form. The workspace's test-only export carries the folder in its name, `@airdesign/mcp/testing/evals`, so the same line holds it. `no-testing-import.test.js` replays the planted imports of the review that failed this move, `packages/doom/src/apply-edit.ts` reaching `packages/doom/src/testing/doom-fixtures-art.ts` and `apps/api/src/server.ts` reaching `apps/api/src/testing/mcp-expected.ts`, which passed every gate before the rule, and the bare-barrel and test-file forms a later review slipped past the first cut.
