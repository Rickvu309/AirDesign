# Checks on the doom core's writes, undo and agent runs

Each entry: what the check promises, the code it covers, its bounds, how to run it alone, its replay, what it leaves out, and its sync: the `covers.json` that records the code the model was last confirmed against. doom is replayed in `tests/doom-replay.test.ts`: `pnpm vitest run tests/doom-replay.test.ts`, and doom-runs in `tests/doom-runs-replay.test.ts`. Together they restate, over property writes, what the edit, undo, run, rerun and person-undo models held for the old stored deck, whose register model is gone.

## doom

A person makes one step that writes two properties on two nodes: the text of a shape (`T`) and the notes of a slide (`N`). They ask for an undo and then a redo. An agent's run may start, write one property once, and stop. A value is the number of the edit that first wrote it and a rev is the number of the edit that wrote last: the file's own is 0, the person's step 1, the agent's write 2, the undo 3, the redo 4. The step and each turn wait in the device's queue and reach the server one at a time (`Sync`); the person's view is the server's fold with the queue on top (`viewOf`), so a turn is asked of the view, even while the step is still on its way. An undo names each property the step wrote where the view still shows the step's rev (`invert`), and its writes carry that rev as `base`. `applyEdit` lands an edit whole or refuses it. A person's edit that lands while the run is running protects its nodes from the run, and a write by a run that is not running is fenced.

- `NeverCoversAgent`: no edit of the person lands over an agent's write the person's view did not hold. A step lands only on the revs its view held, and an undo or redo only where the property still holds the rev it undoes. Harm if broken: Ctrl+Z silently erases what the agent wrote since. Ports person-undo's `NeverCoversAgent`.
- `FoldsApart`: a landed edit changes the value and the rev of the properties it names and of no other. Ports person-undo's `UndoKeepsOtherFields`. The replay also diffs every property of every node after each landing.
- `UndoNamesWhatRemains`, `RedoNamesWhatRemains`: a turn names exactly the properties whose rev in the view is still the one it undoes, and leaves a property someone wrote since alone. This is the one change from person-undo, where a step was whole or dropped: the stored deck had one row per element, the doom has one rev per property (review S1).
- `UndoPutsBack`, `RedoPutsBack`: an undo that lands puts back on every property it names the value the step replaced, and a redo the step's own value.
- `TurnLandsWhole`: a refused edit changes nothing, on any property it names. Ports person-undo's `StepTurnsWhole`.
- `ToldOnlyOverAgent`, `DroppedIsTold`: a step, undo or redo is refused or finds nothing to put back only when the agent wrote a property it names, and the person is told. With no agent write every turn lands. Ports person-undo's `DroppedIsTold`.
- `AgentRespectsPerson`: the agent's write lands only on a node no person wrote during the run. Ports the guard of `decide` (`person-protected`).
- `FenceHolds`: the agent's write lands only while its run is running (`run-fenced`).
- The view: the replay reads `viewOf` at every state and holds each property's value and rev to the model's view, and reads that a second undo of a step that landed puts back nothing (undo's `SecondUndoRemovesNothing`).

Bounds: one step, an undo and a redo, one agent run with one write on either property. 272 states, 492 edges. Run: `pnpm check:specs doom`. Replay: `tests/doom-replay.test.ts` takes all 492 edges from the start through the real `applyEdit`, `invert` and `viewOf` of `packages/doom/src`. The device is a stand-in: it keeps the queue, builds the undo from `invert` on the view, and sends each queued write with its `base` restamped to the real rev of the edit that wrote the property before it, or to rev 0 when that edit never landed. The code now does both in `packages/live/src/doom-queue.ts`: `queueEdit` names the queued edit each base is built on, `landed` gives that base the real rev when the edit lands, and `dropped` takes an edit built on a refused one, or a refused step's provisional rev could equal the rev of the agent's write and let the undo land over it. `packages/live/src/doom-deck.test.ts` holds that case with the real queue; the replay still drives its own stand-in device.

Leaves out: how the editor turns a typing session into edits (`apps/web/src/editor/use-text-session.ts`) and keeps the undo and redo stacks (`undo`, `redo` and `turn` in `packages/live/src/doom-deck.ts`), since the core undoes one edit, and undo-steps ([checks-undo-steps.md](checks-undo-steps.md)) follows the stacks; agent runs side by side and the undo of a run, which doom-runs follows; the fence on an earlier run's undo (`undo`'s `LiveRunKeepsEarlier`: per-property revs replace it, and `doom.property.test.ts` holds that an undo restores exactly the properties nobody wrote since); compaction (`CompactKeepsHead`, `HorizonIsGiven`: the doom has no rows to compact, but `onces` grows by one entry per edit until storage drops old ones); the agent's compare-and-set against a rev it read: a person's landed edit protects the node first, so the model never reaches it (the doom-runs replay probes it at every state, and `apply-edit.guards.test.ts` holds it too); node creation, delete and reparent (`doom.property.test.ts`); `claimed` (the device compiles each agent edit with fresh bases); a property restored by an undo carries the undo's rev, so a node the person edited and undid no longer matches the file's byte for byte.

Planted faults, each put in the model and then in the code:

| Fault                                                | TLC on the planted model                                                       | Replay on the planted code                                                                            |
| ---------------------------------------------------- | ------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------- |
| An undo lands without checking the rev it undoes     | 125 states, `NeverCoversAgent`: the agent writes, then the undo lands over it  | `applyEdit` without its `stale` refusal: a step the model refuses lands and the agent's write is gone |
| A step lands without checking the revs its view held | 47 states, `NeverCoversAgent`: the step lands over an agent write it never saw | the same fault: the step lands, where the model says refused and told                                 |
| The agent ignores the person's protection            | 45 states, `AgentRespectsPerson`                                               | `protect` never marks a node: the replay reads `gT` false where the model says true                   |
| The run fence is gone                                | 4 states, `FenceHolds`: a write before the run starts lands                    | `guardRun` accepts any run: the write lands where the model says fenced                               |
| An undo names every property of the step             | 81 states, `UndoNamesWhatRemains`                                              | `invert` without its rev guard: a second undo of a landed step puts back 2 properties                 |

## doom-runs

Two agent runs, a and b, and a person write the text of a shape (`T`) and the notes of a slide (`N`). Runs a and b belong to two agents (the replay's `aira` and `claude`): a start stops only its own agent's running run, so b's start leaves a running. With one agent for both, b's start would stop a, and the replay fails on the `StartB` edges; specs/agents models one agent's restart. A value is the number of the edit that first wrote it and a rev the number of the edit that wrote last: the file's own is 0, the person's write 1, run a's write 2, its undo 3 and run b's write 5. A run starts with an id no run used before, writes one property once on the rev it holds, and stops; run b starts once run a has started, so the two run at once or one after the other, and writes the text. A person's edit protects the nodes it wrote from each run that is running when it lands (`protect` in `packages/doom/src/apply-edit.ts`). Once run a has stopped the person undoes it once, as `undoRun` in `packages/live/src/doom-deck.ts` does: `invertRun` in `packages/doom/src/invert-run.ts` walks the run's edits newest first and, on each property whose rev is still that edit's, puts back the value the write replaced (`replacedBy`, stored with each agent edit row), sent as the person's edit.

- `RunRespectsPerson`: a run's write lands only on a node no person wrote while that run was running. Ports edit's `ProtectedFromRun` and `GuardedRunRefusesAsProtected`, and rerun's `SecondRunStaysProtected`.
- `ProtectionStaysWithItsRun`: a run starts with no protection, whatever a person wrote during another run. Ports rerun's `GuardBelongsToThisRun`.
- `ProtectedOnlyByThePerson`: only a person's edit protects a node, and only the node it wrote: the text the person wrote, or the property an undo put back. Ports edit's `GuardedOnlyByAPersonEdit`.
- `FenceHolds`: a run's write lands only while the run is running; a write after the stop is fenced (`run-fenced`). Ports edit's and rerun's `StopFences` and run's `StoppedOrEndedRejectsWrite`; the doom model holds a write before the start.
- `UndoTakesBackOnlyItsRun`: the undo of a run changes only the property the run wrote, only while its rev is still the run's, and puts back what that write replaced. The person's write and run b's write stay, before the run's write or after it. Until the undo went edit by edit, it put back what showed when the run started, so when run b wrote the text after run a started and run a then wrote over it, the undo of run a took run b's write away too; the stored deck showed run b's row again. Ports undo's `UndoKeepsPerson`, `PersonRowsStay` and `EarlierUndoKeepsLater`, and rerun's `SecondUndoKeepsOtherRows`.
- `UndoPutsBack`: the undo lands whenever the run's write still shows; with nothing left it is told.
- The replay also lands every person write (edit's `PersonAlwaysLands`: no run holds a person back), diffs every property of every node after each landing, and at every state probes the code: a second start of a run that started is fenced (run's `LaterStartUsesAFreshId`); a running run's write on a node it may write, on a rev older than the property's, is refused `stale` (edit's `AgentSawCurrent`); and after the undo landed, a second undo changes no value (undo's `SecondUndoRemovesNothing`).

Bounds: one person write of the text, run a writes either property once, run b the text once while it runs, one undo of run a. 460 states. Run: `pnpm check:specs doom-runs`. Replay: `tests/doom-runs-replay.test.ts` takes every edge from the start through the real `applyEdit`, `replacedBy` and `invertRun` of `packages/doom/src`, with the composition of `undoRun` restated in the test. Beside the replay, `packages/doom/src/invert-run.test.ts` and `packages/live/src/doom-undo-run.test.ts` hold the cases the model leaves out: a run that writes one property twice around another agent's write (T7), and a layer the run made that someone changed since, which the undo keeps with everything in it and names (T8).

Leaves out: the undo of run b and a run that writes twice, to stay under 500 states; a run's limit and resume and the start of a run while another is live with the same id (run's `LimitEndsLikeStop`, `ResumeContinuesSameRun`, `StartRefusedWhileLive`): the doom has no limit or resume, and refuses only a start that names a known run, so two agents' runs of one deck live at once; claims (edit's `AgentKeepsClaim`, rerun's `NewRunNeverContinuesOldClaim`): the device compiles each agent edit on fresh bases; the device's measured height (edit's `DeviceMeasures`): the doom lays text out on the device and stores no measured box; compaction (undo's `CompactKeepsHead`, `HorizonIsGiven`).

Planted faults, each put in the model and then in the code:

| Fault                                       | TLC on the planted model               | Replay on the planted code                                                                                   |
| ------------------------------------------- | -------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| Run b ignores its protection                | 55 states, `RunRespectsPerson`         | `write` skips the protection: a run writes the text the person wrote during it, where the model says refused |
| A new run inherits another run's protection | 14 states, `ProtectionStaysWithItsRun` | `guardRun` starts a run with every other run's protected nodes: `gbT` reads true                             |
| The undo ignores the rev it takes back      | 163 states, `UndoTakesBackOnlyItsRun`  | `invertRun` without its rev guard: the undo lands over the person's write                                    |
| A stopped run's write lands                 | 25 states, `FenceHolds`                | `guardRun` lets any known run write: run a's write after its stop lands                                      |
| The person's write protects the notes too   | 5 states, `ProtectedOnlyByThePerson`   | `protect` marks every node of the deck: `gaN` reads true                                                     |
| A started run starts again                  | not in the model                       | `guardRun` takes a start that names a known run: the probe's second start lands                              |
| A write on an old rev lands                 | not in the model                       | `write` without its `stale` check: the probe's write lands                                                   |

## Structure on Doom

No model: a property test drives the editor's writes. `apps/web/src/editor/children-keep-place.property.test.ts` runs up to eight steps on four layers, each turned 0°, 30°, 90° or 135°: wrap in a group or a frame (`wrapWrites`), ungroup (`ungroupWrites`), move any layer or group (`moveWrites`), and the person's undo and redo (`invert` with the device's turned revs, as `turn` in `packages/live/src/doom-deck.ts` does). After each step every layer shows where it showed before, or moved by exactly the move when it or a group holding it moved; an undo or redo leaves the slide holding the same layers as before the step it turns. A second test undoes a run that wrapped two layers, as `undoRun` does: the group is gone and the layers show where they did. This ports structure's `ChildrenKeepPlace`, `LeftChildStaysOut`, `EmptiedGroupHoldsNoLayer` and `RunUndoTurnsBackGroup`.

Leaves out: auto layout (Shift+A, padding, Remove auto layout), a drag into or out of a group, and the read set and counts of the stored deck (structure's `ReadSetHeld`, `AbsentEditLeavesCounts`, `StructuralRecord`), which have no doom code; a frame's backdrop (`BackdropOnlyInFrame`): a doom frame paints its own fills. The run's undo of a group the person moved since (`PersonMoveKeepsAgentGroup`) differs from the stored deck, which refused it: the doom keeps the group with its layers where the person put it, takes back the rest of the run, and names the group as kept (`invertRun` in `packages/doom/src/invert-run.ts`, held by `invert-run.test.ts`, `doom-undo-run.test.ts` and `tests/browser/editor-agent-undo-kept.spec.ts`).

Found: a group around a hugging group jumped on ungroup, by half the difference between the size the inner group stored and the size it showed (#1406).

## Read base

An edit can carry the revision of the whole fold it read. The device remembers every pending edit that contributed to that fold. Those edits must land at consecutive revisions from the authoritative base. The server resolves an accepted `once` after checking ownership, then checks the read base against the head used by its SQL compare-and-swap.

- `ExactBase` holds that a guarded edit can land only immediately after its read base.
- `Predecessor` holds that the second edit can only land after its predecessor and that a rejected predecessor takes its dependent with it. A queued component refresh may then prepare a new edit from the accepted fold.
- `Once` and `OneRowPerOnce` hold that an edit with a lost reply is still accepted and retrying it adds no row. An empty guarded edit also adds no row.

Bounds cover two guarded edits, one empty edit, one lost reply and one interleaving from another writer. Run `pnpm check:specs read-base`. The replay in `tests/read-base-replay.test.ts` drives every edge through `createDoomDeck` and the real Doom fold. It checks the accepted revisions, local view, queue, refusals and the revision returned by a retry. The Postgres test pauses the SQL update and lets another writer win the compare-and-swap. The offline browser suite also uses the real API to cover an unguarded predecessor that lands too late and a consecutive chain after a dropped reply. Component ownership and grouped inverses are outside the model.

The pre-change Postgres tests refused the guarded command as malformed. With the guard removed, the model mutation lets the second edit land at the wrong revision and breaks `ExactBase`.

Sync uses `specs/read-base/covers.json`.
