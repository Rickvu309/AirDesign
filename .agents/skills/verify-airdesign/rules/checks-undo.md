# Checks on a person's own Undo and Redo

Same fields as [checks-document.md](checks-document.md). person-undo is replayed in `tests/spec-replay.test.ts`; multi-step in `tests/multi-step-replay.test.ts`; typing in `apps/web/src/typing.test.tsx`, which renders the editor's undo parts in jsdom: `pnpm vitest run apps/web/src/typing.test.tsx`. A design panel change, Undo or Redo made before the server answers is device-queue in [checks-device-queue.md](checks-device-queue.md). The undo of an added or removed element is element in [checks-element.md](checks-element.md), and a run's own Undo is undo there and slide-undo in [checks-slides.md](checks-slides.md).

## person-undo

A person's Undo and Redo of one step that edited the text of two elements, A and B, beside an agent run that writes A's text or moves A's box.

- `UndoShowsBefore`: an undo or redo shows exactly the text it went back to, on every element of the step.
- `NeverCoversAgent`, `AgentRowStays`: a person's undo never lands over an agent row that shows on a field the undo names, and only the run's own Undo hides that row. Harm: a person's Ctrl+Z erases Aira's work.
- `UndoKeepsOtherFields`: a field the step does not name keeps what showed, so the person's text undo lands while Aira's move of the same element shows, and leaves the move. Harm: Ctrl+Z on a text puts back a box an agent moved, or refuses because of it.
- `StepTurnsWhole`: a step lands on every element it names or on none. Harm: Ctrl+Z after one change to two titles turns back one of them.
- `DroppedIsTold`: an undo that changed nothing is always told.

Bounds: up to four person steps, each one row on each element, one agent row on A's text or A's box, 185 states. Run: `pnpm check:specs person-undo`. Replay: `tests/person-undo-replay.ts` through `undoOf`, `redoOf` and `decide` on a `{ steps }` undoable, with the step's elements on different slides in the order B then A; on every Undo and Redo edge the step of A alone must agree with the two-element step. `{ steps }` is the one undo kind the editor records for a canvas gesture, a design panel change and a speaker notes edit (`editableSlide`, `applyChange` in `apps/web/src/design/trait-edit.ts`, `useNotes`). A text format change records its own entry named `format`, and a design panel change on several chosen elements one step naming each of them. `joined` in `apps/web/src/undo-list.ts` merges the entries of one session that name the same elements in the same order, keeping each element's first before and last after, so one visit to a number field is one step. The model takes a step as recorded: how the editor builds and merges steps is outside it, and typing models the merge for one box. Code: `undoOf`, `redoOf`, `turn` and `turnCommands` in `packages/document/src/person-undo.ts`, which land a step on all its elements or none through `stepCommands` and `applying`, compare each field a step names with `shows` over `shownPatch` (`packages/document/src/decide.ts`, the node's floor and its visible rows folded per trait field by `netPatch`), read a format 1 value as the trait the step names (`holderOf`, so a notes step turns on a device register that holds no index), and write the step back as format 1 values with `formatOne` (`packages/document/src/row.ts`) when every field it names has one, and as one row `{ v, patch }` otherwise, such as a fill or a field back to `"opening"` (`person-undo.test.ts`), and the stack in `apps/web/src/undo-list.ts`, which sends every command of a turned step, a row through the queue's `enqueueRow`. Leaves out: box undo, slide undo (`slideUndoable`), stacking (`element-order` and the stack branch of `turn`), and notes edits, which take the same path as text. The undo of an added or removed element, with another tab and an agent's run in between, is covered by element. An undo while typed edits are still being recorded or sent, and the browser's own undo, are typing.

Sync: `specs/person-undo/covers.json`.

## multi-step

A person chooses two elements, A and B, with Shift+click and presses Delete once, then undoes and redoes that one step, beside an agent that deletes one of them or writes in one. A may have an animation in the file, which the device refuses to delete.

- `OneStep`, `StepNamesWent`, `SaysRefused`: one Delete records one undo step that names only the elements that went, and the person is told each chosen element that could not be deleted, in the existing refusal words. Harm: Delete with two shapes chosen removes only the last one clicked, or Ctrl+Z after it tries to bring back an element that never went.
- `StepTurnsWhole`: one undo brings back every element the Delete deleted that no agent deleted, and one redo leaves none of them. A turn skips an element already in the state it wants and lands on all the others or on none. Harm: Ctrl+Z after deleting two shapes brings back one.
- `AgentGoneStays`: no undo or redo of the person brings back an element an agent deleted. Each turn leaves on the other list a step that names only the elements it turned (`turnBack` keeps the step `undoOf` or `redoOf` returns), so a redo that skipped an element an agent deleted is followed by an undo that leaves it gone. Harm: an agent deletes a shape, and the person's Ctrl+Z brings it back.
- `NeverWipesAgent`: a redo lands on none while any element it would delete shows an agent's row written since the step, per element as `stillShows` reads it. Harm: Ctrl+Shift+Z deletes text an agent wrote in a shape the undo brought back.
- `DroppedIsTold`: an undo or redo that changed nothing is always told.

Bounds: two elements on one slide, one Delete, one agent change, three turns, 69 states. Run: `pnpm check:specs multi-step`. Replay: `tests/multi-step-replay.test.ts` reaches every state through the engine on a deck indexed with A animated or not: `Delete` is `elementsUndoable` over every element that shows and `call("commit_edits")` of what it names, `Undo` and `Redo` are `undoOf` and `redoOf` and `commit_edits` of their commands, `AgentDelete` is `call("delete_element")`, `AgentWrite` is `start_run`, `edit_deck` and `stop_run`. It checks what shows, what the step names, and that the device refuses A exactly where the model says. Code: `elementsUndoable`, `elementsTurn`, which `turn` calls for an `{ elements }` step and which lands through `applying`, all or none, and `stillShows` in `packages/document/src/person-undo.ts`; `turnBack` in `apps/web/src/undo-list.ts`; `removals`, `removalPlan`, `planElement` and `storePlan` in `apps/web/src/element-edit.ts` (the editor paints a Delete ahead and the insert lane stores the planned removals, `changeElement` in `apps/web/src/editor/inserts.ts`), which say each refusal once and record one step for what the device took; the Delete key in `useMoves` in `packages/render/src/slide-moves.ts`, which passes every chosen element the canvas can move. The rest of `useMoves`, drags, resizes and nudges, which hold the element's box in the paint store while the gesture lasts, is outside the model. Leaves out: another tab bringing an element back (element models it for one element; `packages/document/src/person-undo.elements.test.ts` tests that an undo skips one already back), so an undo after another tab brought an element back and an agent then deleted it is not checked, and the code brings it back, since a turn reads only whether an element shows (known bug, an `it.fails` test in `packages/document/src/person-undo.elements.test.ts`); the app's own refusal of an animated element or a group (`removalRefusal`, tested in `apps/web/src/element-edit.test.ts`); move, align, paste and cut of several elements; an agent grouping a chosen element, which the device refuses (`group-box`) so a turn lands on none. `tests/browser/delete-chosen.spec.ts` drives the Delete, Ctrl+Z, Ctrl+Shift+Z, a reload and an export in the app.

Sync: `specs/multi-step/covers.json`.

## typing

A person types two letters of speaker notes, then two over a text box, and presses Ctrl+Z, later Ctrl+Shift+Z, while what they typed is still on its way. Each edit is written to the device at once. A keystroke's undo record lands once the device answers and the session's text before is read (`editText` in `apps/web/src/editor/editable-slide.tsx`); a notes edit's lands in the task the device's answer comes in (`useNotes` in `apps/web/src/notes-edit.ts`), and neither waits for the server. Every command takes its place in the undo list when the person asks for it (`hold` in `recordsInFlight`), and its record lands only after every record held before it. Each edit then goes to the server, and the box stays busy until its keystrokes got there. A text is a number: 0 the text before the typing session, 1 its first letter, 2 the whole new text. The undo list is a number whose digits are its entries (1 and 2 the notes, 3 and 4 the box), because the graph reader takes only plain values.

- `UndoRestoresBefore`: one undo after typing holds and shows, in the element it turned, the text from before the typing session, never a part of the new text. Harm if broken: Ctrl+Z straight after typing "New" over "Old" shows "N", PR 427's fault.
- `NeverPartOfNew`: once the whole new text is typed, the box never shows only its first letter.
- `NoUndoOnMissing`: an undo or redo never reads a list that is missing a record already typed. The ghost `missing` is set when the undo reads the list (`Turn`).
- `TurnLands`: every undo and redo asked for after typing lands. Harm if broken: Ctrl+Z straight after typing does nothing, or says nothing changed.
- `ShownIsDeck`: after an undo or redo, the box and the notes show what the deck holds. Harm if broken: the box keeps the typed text while the deck went back.
- `RedoRestoresTyped`: a redo brings back the whole typed text.
- `UndoTakesLastTyped`: the element one undo turns is the one the person typed in last. Harm if broken: on a slow network the first Ctrl+Z after typing over a text undoes the speaker notes instead, the fault from `3b0c63e1` that PR 441 pinned.

Bounds: one box with two keystrokes, one slide's notes with two edits typed before the box, one undo, then one redo, no typing after the first Ctrl+Z. 248 states, 577 edges. Run: `pnpm check:specs typing`. Replay: `apps/web/src/typing.test.tsx` renders the real `Passage`, `NotesBar` (opened), `useUndoList`, `useUndoTurn` (with its `useUndoKeys`) and `useNotes` in jsdom over a real paint store and the parts of `scripts/pptx-fixtures/clean.pptx`, and takes all 577 edges in 184 walks from the start. So the undo's own waits, `turnBack`, `showTurned`, the repaint as the person and `notesShown` are the product's, through `recordsInFlight`, `recorded`, `liveRepaint`, `busyElements`, `showText`, `commitEdit`, and `decide`, `undoOf` and `redoOf` on a register. The device (`connect`) is a stand-in: a write lands on the register at once, its answer waits for the model's `RecordNotes` or `RecordText`, its upload for `UploadNotes` or `UploadText`, and the undo's deck read for `Turn`. After every step the test compares every model variable with the code (the box's text in the DOM, the notes field's value, the deck, the undo and redo lists, the counts), checks the box is busy exactly while a keystroke is unsent, and checks the undo reaches its deck read exactly when the model's waits are met. `KeyUndo` and `KeyRedo` press the keys on the box, or on the notes field when only notes were typed, and check the browser never gets them; `MenuUndo` sends `historyUndo` to the same place and checks the box or the notes field refuses it. Code: `recordsInFlight`, `recorded` and its merge `joined`, `turnBack` in `apps/web/src/undo-list.ts`, `liveRepaint` and `busyElements` in `apps/web/src/live-repaint.ts`, `useNotes` in `apps/web/src/notes-edit.ts`, `undoKey` and `useUndoKeys` in `apps/web/src/editor/undo-keys.ts` (a field marked `data-person-undo` hands the keys to the person's undo), the `beforeinput` refusals in `packages/render/src/passage.tsx` and `apps/web/src/editor/notes-bar.tsx`, `turn` and `showTurned` in `useUndoTurn` in `apps/web/src/editor/use-undo.ts`, and `editText` in `apps/web/src/editor/editable-slide.tsx`.

Leaves out: that each keystroke is also painted ahead until the device wrote it (`typedAhead` in `editableSlide`), so a change planned straight after typing sees the typed words; `apps/web/src/editor/painted-ahead.test.ts` tests it. Also an insert still waiting in the editor's store lane (`storeLane` in `apps/web/src/editor/store-lane.ts`): a keystroke, and a box's fit after it, writes only once every insert queued before it is stored, so no row on a new layer reaches the device before the layer; the model has no insert, so the lane is always empty in it. `apps/web/src/editor/editable-slide.test.tsx` holds a lane entry and checks that the keystroke waits, and `tests/browser/insert-order.spec.ts` checks the device's row order. Also another writer's text on the box while the person's own keystrokes still hold it busy. A repaint from the server leaves a busy box and marks it missed (`missed` in `busyElements`, in `liveRepaint` and `paint`) without counting its text as landed, and when the box's last hold lets go the editor reads the device again and paints it (`showFreed` in `apps/web/src/editor/use-deck-paint.ts`); `apps/web/src/live-repaint.test.ts` tests both, and the look state `box-undo-changed` drives an agent's write in a browser. Also a text format change, which `Passage` reports as a `format` edit; `editText` records it as a session of its own and ends the typing session, so a keystroke after it opens a new entry and never joins it. A number field in the design panel opens a session when it takes the focus (`useUndoTurn`); the box and the notes field are not such fields. The replay restates `editText` instead of driving it, since `editableSlide` needs a painted deck: it holds the box and the records, reads the text before at the session's start and records in the paint step. `tests/browser/person-undo.spec.ts` drives it in a browser. The model takes the text before as read from the device before the first keystroke's write lands. They are two IndexedDB transactions in `packages/live`, and IndexedDB runs them in the order they were created; the read's is created first only because `openDeck` reaches `heldView` in as many awaits as `enqueue` reaches `changeHeld`, and `editText` asks for the read first. `packages/live/src/cache-order.test.ts` holds the read on the device while the write is asked for and fails if one more await flips them. It takes the device as answering writes in typing order (`changeHeld` reads nothing after its write, tested there; out of order TLC breaks `TurnLands`, 94 states), and a notes edit as recording in the task its answer comes in, so a keystroke records after every notes edit typed before it (`RecordText`). Uploads finish in any order in the model; the device sends them one at a time in call order (`serial` in `packages/live/src/cache.ts`). Also left out: typing after Ctrl+Z, notes typed after the box, a second undo, the notes field's `onChange` (the replay calls `useNotes`'s `edit` as the field does; `tests/browser/notes-typing.spec.ts` types into the field), boxes, slides and added elements, the server's answers that repaint (`reconcile`), and agent runs (person-undo).test.tsx`checks. Slide commands, added and removed elements, pictures and box moves record once the device answers and before they go to the server, each in the place it took when asked, so a group straight after typing lands above the typed edit even when the keystroke's record comes later (the journey`group-text-copy`). `apps/web/src/editor/editable-slide.test.tsx`drives the real`editText`and`deckInserts`: a shape added while a keystroke's answer is held lands above the text edit, and a placed text box stays beneath the words typed into it; `apps/web/src/undo-list.test.ts` checks the order of holds. A drag notes its box in the unsaved journal before that answer (`noteBoxes`in`editableSlide`); the undo record still waits for the device.
