# Checks on undo and redo made offline

The entry has the same parts as those in [checks-doom.md](checks-doom.md). [checks-undo-steps.md](checks-undo-steps.md) holds the undo and redo stacks it builds on.

## undo-offline

One device's undo and redo stacks while the tab is offline, beside another tab that changes the deck once, and the replay of the queued turns when the tab reconnects (`drain` in `packages/live/src/doom-deck.ts`). Three properties: the title's text (`T`), the card's box (`C`) and the deck's name (`N`). The title has the role `title` and the deck name follows it, so every write of the text comes with a write of the name. The person has saved two steps: a nudge of the card to 1, then a step that writes 2 to the text and the name, or to the text, the name and the box in one edit. The tab goes offline once and comes back. Another tab, once and at any time, deletes the title (and sets the name back to blank in the same edit unless it is blank already), renames the deck, or retypes the title (the name follows it); online the tab sees it at once, offline only when it reconnects. A press works on what the tab shows, as in undo-steps: it puts back what the step replaced on each property whose last writer is the step or a turn and whose layer the tab shows, and offline the turn paints at once and waits in the queue. On reconnect the queue replays in order. The deck refuses a write to a deleted layer (`missing`) and a write whose base is older than what the other tab wrote (`stale`), the whole edit either way. For either, and for any content refusal that catching up resolves (`catchingUpResolves` in `packages/live/src/turn-replay.ts`: all but `shape`, `limit`, `person`, `run-fenced` and `last-slide`), the tab catches up and sends the refused turn again with only the writes that would still land (`onStandingOnly` in `packages/live/src/turn-replay.ts`): not a write to a property the other tab wrote since the press (the ownership test of `invert`), and only the writes `onStandingLayers` keeps on the server's deck, the same judge as an undo online. Sent with the property the other tab wrote, the whole edit would be refused `stale` and the card would jump back. A turn with none left is taken off quietly with the step that would put it back (`skipped` in `packages/live/src/doom-queue.ts`), as an undo online answers `nothing`. An edit queued after it that was built on a write the turn lost gets the base that write had (`trimmed` in `packages/live/src/doom-queue.ts`, which `skipped` calls with nothing kept), so the other tab's write refuses it `stale` in turn and it is trimmed the same way. A press queued behind a trimmed or replanted one was built from the untrimmed step, so `onStanding` in `packages/live/src/turn-replay.ts` builds it again in queue order (`rewritten` in `packages/live/src/doom-queue.ts`): `invert` from the step as it now is, against the deck the queue leaves it, with the same ownership test and `onStandingLayers`. Up to two presses, at most two queued.

- `NeverLosesAStep`: online, every value the person sees that their own step or turn wrote last can still be turned back: the edit that wrote it waits on a stack. Harm if broken: nudge the card, then nudge it and type in the title in one step, go offline and press Ctrl+Z, another tab deletes the title, renames the deck or retypes the title, and on reconnect the undo is set aside whole: the card jumps back, and both steps are lost for good (verdicts 1507-1fb8aa5 finding 2, 1567-23481f5).
- `NothingJumpsBack`: reconnecting moves no value the person sees on a layer that still stands and that the other tab did not write. Harm if broken: the card the offline undo painted jumps back under a set-aside notice, though only the title, which is gone, refused it, or the name or the words the other tab wrote, which the undo would restore (verdicts 1567-08dae41, 1567-23481f5).
- `Agreed`: online, the tab shows what the server holds.
- The replay also reads, at every edge, what the tab shows and what the server holds, the edit that wrote each last, how many turns wait in the queue, and what the press answered or whether reconnecting set anything aside.

The set-aside notice stays for what it says: an edit the deck refused that the person must make again. A turn whose writes all fall on deleted layers is not one, since online the same press answers `nothing`.

Bounds: two saved steps, one offline spell, one edit by the other tab (delete, rename or retype), two presses. 414 states. Run: `pnpm check:specs undo-offline`. Replay: `tests/undo-offline-replay.test.ts` drives all 664 edges from both starts through the real `createDoomDeck`, `openDoomDeck` and `memoryDoomRemote`, the person's tab cut off from the server by a wrapper and another tab on the same server: each edge replays the shortest path to its source on a fresh deck, then the edge. `packages/live/src/turn-replay.test.ts`, `packages/live/src/turn-replay-queued.test.ts`, `packages/live/src/doom-queue.test.ts` and `tests/browser/editor-offline-tabs.spec.ts` hold the cases beside it: an undo queued after the refused one, a redo queued behind an undo, a turn left with nothing, the same for an agent run undone while the other tab changes the deck, a refusal that stays set aside, and two real tabs, one offline.

Leaves out: frames and moves, where `onStandingLayers` judges the queued turn against the server's deck with the rev the tab knew at the press and the frame each layer sat in then, so a frame someone moved a layer into after the press is kept (`heldFrames`) and a layer the other tab moved into another frame keeps where it sits there (`strayedFrom`; `turn-replay.test.ts` holds one), and a redo or an undo queued behind an undo that replants a layer into the frame it sat in, which must keep the other tab's nudge as the same presses online do (`turn-replay-queued.test.ts` drives both orders against the same presses made online); a refusal catching up cannot resolve: `shape`, `limit`, `person`, `run-fenced`, `last-slide`, and the ones that are not about the edit's content (`size`, `field`, a lost session, a trashed or missing deck, storage), which still set the turn aside with a notice or stop the queue as before (`turn-replay.test.ts` holds the four content ones); a `stale` left after the resend, which is the same property written by both tabs after it, not before; the online press, which has no gap for the name: `invert` already skips a property whose last writer is not the step or a turn of this tab, and `turn-replay.test.ts` holds that case; a deck whose name does not follow the title yet (the first typing then also writes `nameFollows`, so an undo that only has that flag left is not taken off quietly, online or offline); a queued turn after a reload, when the stacks are gone and a refused turn is set aside as any edit; typing and other person edits made offline on a layer another tab deletes, which are set aside with a notice as before; agent runs in the model (`undoRun` needs the server, and a run's undo refused in flight takes the same path through `drain`; `turn-replay.test.ts` holds the rename, retype and delete).
