# Checks on the scene core's writes, undo and agent run

Same fields as [checks-document.md](checks-document.md). scene is replayed in `tests/scene-replay.test.ts`: `pnpm vitest run tests/scene-replay.test.ts`. It restates, over property writes, what typing, person-undo, undo and field-fold hold for the stored deck ([checks-undo.md](checks-undo.md), [checks-field-fold.md](checks-field-fold.md)). Those four keep checking the stored deck until the scene replaces it.

## scene

A person makes one step that writes two properties on two nodes: the text of a shape (`T`) and the notes of a slide (`N`). They ask for an undo and then a redo. An agent's run may start, write one property once, and stop. A value is the number of the edit that first wrote it and a rev is the number of the edit that wrote last: the file's own is 0, the person's step 1, the agent's write 2, the undo 3, the redo 4. The step and each turn wait in the device's queue and reach the server one at a time (`Sync`); the person's view is the server's fold with the queue on top (`viewOf`), so a turn is asked of the view, even while the step is still on its way. An undo names each property the step wrote where the view still shows the step's rev (`invert`), and its writes carry that rev as `base`. `applyEdit` lands an edit whole or refuses it. A person's edit that lands while the run is running protects its nodes from the run, and a write by a run that is not running is fenced.

- `NeverCoversAgent`: no edit of the person lands over an agent's write the person's view did not hold. A step lands only on the revs its view held, and an undo or redo only where the property still holds the rev it undoes. Harm if broken: Ctrl+Z silently erases what the agent wrote since. Ports person-undo's `NeverCoversAgent`.
- `FoldsApart`: a landed edit changes the value and the rev of the properties it names and of no other. Ports field-fold's `FoldsApart` and person-undo's `UndoKeepsOtherFields`. The replay also diffs every property of every node after each landing.
- `UndoNamesWhatRemains`, `RedoNamesWhatRemains`: a turn names exactly the properties whose rev in the view is still the one it undoes, and leaves a property someone wrote since alone. This is the one change from person-undo, where a step was whole or dropped: the stored deck had one row per element, the scene has one rev per property (review S1).
- `UndoPutsBack`, `RedoPutsBack`: an undo that lands puts back on every property it names the value the step replaced, and a redo the step's own value. Ports field-fold's `UndoPutsBack` and typing's `UndoRestoresBefore`, `RedoRestoresTyped`.
- `TurnLandsWhole`: a refused edit changes nothing, on any property it names. Ports person-undo's `StepTurnsWhole`.
- `ToldOnlyOverAgent`, `DroppedIsTold`: a step, undo or redo is refused or finds nothing to put back only when the agent wrote a property it names, and the person is told. With no agent write every turn lands. Ports typing's `TurnLands`, person-undo's `DroppedIsTold` and field-fold's `ToldOnlyOverAgent`.
- `AgentRespectsPerson`: the agent's write lands only on a node no person wrote during the run. Ports the guard of `decide` (`person-protected`).
- `FenceHolds`: the agent's write lands only while its run is running (`run-fenced`).
- The view: the replay reads `viewOf` at every state and holds each property's value and rev to the model's view. This is typing's `ShownIsDeck`, and the replay also reads that a second undo of a step that landed puts back nothing (undo's `SecondUndoRemovesNothing`).

Bounds: one step, an undo and a redo, one agent run with one write on either property. 272 states, 492 edges. Run: `pnpm check:specs scene`. Replay: `tests/scene-replay.test.ts` takes all 492 edges from the start through the real `applyEdit`, `invert` and `viewOf` of `packages/document/src/scene`. The device is a stand-in: it keeps the queue, builds the undo from `invert` on the view, and sends each queued write with its `base` restamped to the real rev of the edit that wrote the property before it, or to rev 0 when that edit never landed. A restamp is not in the code yet: `live` must do it when it carries writes, and must drop an edit built on a refused one, or a refused step's provisional rev can equal the rev of the agent's write and let the undo land over it.

Leaves out: typing's pipeline of keystrokes, their records and the undo list's joining of one session's records into one entry (`apps/web/src/undo-list.ts` keeps it; the core undoes one edit); run undo of a second run and the fence on an earlier run's undo (`undo`'s `LiveRunKeepsEarlier`: per-property revs replace it, and `scene.property.test.ts` holds that an undo restores exactly the properties nobody wrote since); compaction (`CompactKeepsHead`, `HorizonIsGiven`: the scene has no rows to compact, but `onces` grows by one entry per edit until storage drops old ones); the agent's compare-and-set against a rev it read: a person's landed edit protects the node first, so the model never reaches it (`apply-edit.guards.test.ts` holds the compare-and-set itself); node creation, delete and reparent (`scene.property.test.ts`); `claimed` (the device compiles each agent edit with fresh bases); `BytesWhenUntouched`: a property restored by an undo carries the undo's rev, so a node the person edited and undid is no longer byte for byte the file's; a write to the scene always costs the node its passthrough.
