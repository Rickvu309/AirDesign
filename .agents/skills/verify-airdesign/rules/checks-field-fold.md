# Checks on how a design panel field folds

Same fields as [checks-document.md](checks-document.md). field-fold is replayed in `tests/field-fold-replay.test.ts`: `pnpm vitest run tests/field-fold-replay.test.ts`. The device queue under a panel change, its batches, once and lost answers, is device-queue in [checks-device-queue.md](checks-device-queue.md). An undo beside an agent's run, and the run's own Undo, is person-undo in [checks-undo.md](checks-undo.md).

## field-fold

A person clicks Reset fill on a shape, then sets one more field in the design panel (the fill colour, the opacity or the font size), then clicks Undo twice. An agent's run may set the colour or the opacity, or change the theme colour the shape's style names, on the server. The shape's file fill is accent 1 at 60% opacity, its style's fill is accent 2, and its text sets no size, so it shows the size its master gives it. A row sets a field, sends the colour back to `inherit`, or sends a field back to `opening`; a node shows its rows folded field by field. The export writes that fold over the file's own bytes, and the panel and the canvas both read what the export wrote. An edit is a digit that names its field (colour 1 the file's, 2 inherit, 3 the person's, 4 the agent's; opacity 5 the file's, 6 the person's, 7 the agent's; size 8 the file's, 9 the person's), and rows and the undo list are numbers whose digits are their entries, because the graph reader takes only plain values.

- `FoldsApart`: a row changes the fold of the field it names and of no other, on the device and on the server. Harm if broken: an opacity change after Reset fill brings back the file's colour, or a person's colour drops an agent's opacity.
- `ShownApart`: an opacity row never changes the colour or the size the panel and the canvas show, and a size row never changes the colour or the opacity.
- `ClearShowsInherited`: a reset colour shows and paints the colour the style inherits, from the theme as the device last read it, in quiet ink while no row sets the opacity. With the opacity set, the export copies the inherited fill as the shape's own with that alpha, so the panel draws it in full ink and offers Reset fill again; a second reset writes a row and records no step.
- `UndoPutsBack`: an undo that lands puts back on the device exactly the edit the field held when the person made the step: the file's value, a set value or inherit. A step made while an agent's row sat on the server unread puts back what the device showed, so the undo covers that row; person-undo's `NeverCoversAgent` guards only a row that shows.
- `BackToFile`, `BytesWhenUntouched`: with no agent, two undos bring the export back to the slide's own bytes, and once synced the server's rows fold to nothing. The export writes the slide's own bytes exactly while every field shows the file's value; an undone font size writes the file's text as a value, which the export leaves alone because it already shows.
- `ToldOnlyOverAgent`: an undo changes nothing only when the agent set the same field and the device read it. The person's own rows, pending or not, never make an undo fail.
- The panel shows what paints: the replay reads the panel and the canvas apart and holds both to the model. The model has one value for each.
- `ColourKeepsAlpha`: the person's new colour keeps the opacity the panel and the canvas showed. Picked over the inherited fill after Reset fill, it keeps the inherited fill's 100%, not the file's 60%: the fold keeps no trace of the reset, and `alphaKept` in `packages/pptx/src/alpha-codec.ts` keeps the alpha of the file's own fill the colour is written over unless the colour names one, so `panelOf` writes a colour picked over an inherited field with the alpha that field's opacity showed (`atShownAlpha` in `apps/web/src/design/shown-alpha.ts`). Picked over the agent's colour, it keeps the file's 60%, which is what showed. The model reads which colour the step replaced from the undo list. Harm if broken: the shape fades to an opacity nobody chose (from `8d57af20` to the fix). An agent's colour after a reset still brings back the file's 60%: the agent saw no panel, and the model holds it as what shows. The replay pins that gap in `it.fails("keeps the reset fill opacity when an agent then sets the colour")`.

Bounds: one shape, Reset fill, then one of the three changes, then two undos; one agent change; no Redo. 435 states, 789 edges. Run: `pnpm check:specs field-fold`. Replay: `tests/field-fold-replay.test.ts` takes all 789 edges from the start. A click is the real `applyChange` (`apps/web/src/design/trait-edit.ts`) with the change the panel's row builds (`panelOf` and `rebasedChange`), and the step lands in the list through `recorded`; Undo is the real `turnBack` (`apps/web/src/editing/undo-list.ts`). The device link is a stand-in: it keeps the server's deck as the device last read it and the pending rows, and plays each row with `decide` as `landed` in `packages/live/src/slide-replay.ts` does. Sync sends the pending rows to the engine's `commit_edits` and reads the deck back; an agent change is `start_run`, `edit_deck` with a `set` and `stop_run` through the engine's `call`. After every step it compares each field's fold on the device and on the server (`landedPatch`), the undo list and whether the person was told, the panel's fill colour (resolved with the theme of the deck it shows), its quiet ink, the fill's opacity the Opacity row reads and the font size row and its quiet ink, the canvas's fill colour and alpha from `paint` in `apps/web/src/deck-paint.ts`, and whether `exportedParts` writes the slide part's own bytes. The panel's reads restate `fieldsRead` in `apps/web/src/editor/panel-fields.ts` for the fill, the alphas and the text style. Code: `netPatch`, `beforeOf` and `shows` in `packages/document/src/row.ts`, `landedPatch` in `decide.ts`, `traitPatch` and `planNode` in `change.ts` (a reset sends `null`, which becomes `inherit`; the opacity writes the alpha of the fill, the line and the text), `undoOf` in `person-undo.ts`, `planned` and `landedBefore` in `apps/web/src/design/trait-edit.ts`, `panelOf` in `apps/web/src/design/panel.ts`, `exportParts` and `writeFields` in `packages/pptx`, with `fillXml`, `fadedFill` and `alphaKept` for the fill, and `applySet` in `packages/engine/src/apply-change.ts`.

Leaves out: the device queue's batches, once and lost answers (device-queue); the agent's run Undo and the guard on a person's rows during a run (person-undo, turn); Redo, a change before the reset and a second agent change; the line's and the text's alphas apart from the fill's (the Opacity row writes all three and shows Mixed when they differ; the model holds the fill's); gradients and patterns; an agent's text write beside a person's font size, which are last writer wins on the one text field (typing, person-undo); the canvas's paint of the font size, which comes from the text the paint store holds, the same value the panel reads. The swatch the element panel draws is outside it: `LiveElementDesign` takes its palette's theme from the deck it shows, so after a theme change a fill that names a theme colour draws in the colour the canvas paints (`apps/web/src/editor/live-design-panel.test.tsx` and `tests/browser/theme.spec.ts`).
