# Checks on stored slide groups

`Grid` checks six opening slides, same-row and below-row additions, a duplicate, source-head movement, deletion and restoration, guarded undo and redo, and device adoption. Its below-add paths include a foreign source-tail append, two below-adds, a deleted anchor, a colliding birth, foreign content in the added row and an unsafe redo after another tail append. It has 222 reachable states.

`Partition`, `NoEmptyRow`, `HeadsUniqueOrdered` and `RowMajor` require each live slide to belong to exactly one nonempty row, with live unique heads in presentation order. `ForeignRowKept` prevents a restored head or below-add taking a foreign slide from its row. `BelowSingleton` requires each accepted below-add to create its own row. `SameAcceptedPrefix` requires server and device projections to agree when they hold the same accepted prefix.

Run `pnpm check:specs grid`. `tests/grid-replay.test.ts` drives all edges through `decide`, `slideUndoable`, `undoOf`, `readSlideState` and `gridGroups`. Adoption in this replay uses the structural decoder and joint fold; IndexedDB envelopes and once delivery are covered separately by the live format tests and the lost-answer and tabs replays.

The model uses six opening ids and two additional ids. It abstracts fractional keys to relative positions and checks these bounded lifecycle paths, rather than arbitrary permutations or all foreign interference. `grid-order.property.test.ts` generates 300 longer traces through real keys, including new-row additions, checks partition and decoding, and reverses each accepted edit. `grid-order.test.ts` covers initialization, head transfer, two tabs and guarded inverse interference. `grid-add.test.ts` checks application-time tail resolution, section inheritance, the 49-to-50 transition and atomic refusal at 50. `packages/live/src/grid-add.test.ts` covers offline reload, accepted-prefix replay, byte-identical sealed resends after a lost answer and an offline add followed by undo. Atomic group moves in same/new/keep placement, source-row removal, guarded whole-row undo/redo, stale membership refusal and independent foreign-gap insertion are modelled and replayed. Split and join remain outside the model and API. `grid-move.test.ts` and the generated traces cover plural moves with real fractional keys; live tests cover reload, journal recovery and lost answers.

A planted stale-anchor implementation failed the concurrent-tail unit case. A planted model that put the new head before the foreign tail slide violated `ForeignRowKept`. Both faults were removed before the passing run.

Person-undo continues to describe node-field interference; Grid covers its new structural spot/head branch. Slide-undo continues to describe run fencing and all-or-none run undo. Offline describes the node queue. Tabs and lost-answer retain their transport bounds; lost-answer now sends a tagged anchored add.

Sync: `specs/grid/covers.json`.

The plural extension retains exact row membership only for keep, and guards all moved spots and the existing head/neighbor dependencies for group moves. Grid abstracts server and device adoption; once-only delivery remains in live tests.

The extension was challenged by removing the complete-row refusal: the Grid replay failed on `RefuseStaleRow` because the code applied a move instead of refusing it. The fault was removed. TLC also checked the eight invariants afresh through the statechart runner: 125 states and 164 steps.

The selected-slide paths model deletion across row heads, duplication after the last selected slide, one guarded Undo for each edit, refusal of an empty deck, and refusal of a colliding copy id. The replay reaches each path through the document commands. The document test checks the actual 50-slide limit, and the live tests exercise offline replay and a byte-identical resend for both commands.

The versioned paths publish section starts, pack three complete singleton sections together and choose the opening partition from the first command's version, and replay a later command from the other version. `VersionedDefault` checks the resulting heads. `grid-version.test.ts` in document also replays a recorded version-one log with and without the upgraded index, and generates section lengths to check complete-section packing, wrapping and the frozen unsectioned default. The live test recovers the version-two edit from its journal and sends a new import's index before its first edit.

The device saves section starts in a format-stamped slot and reads it in the same transaction as the edit rows. The live version test checks that a fresh import has an empty edit log and can still recover a version-two edit offline.

The before-anchor move can change row membership while keeping slide order. Grid checks a group prepended to a row, Undo, device adoption, refusal after the anchor is deleted, and a before-anchor move as the first edit on a sectioned deck. A planted insertion after the anchor failed the replay with slide 5 still at the row head.

Version three plans a command against slide groups, not rows. `slideGroups` in `packages/document/src/slide-groups.ts` reads every log: with no grid command it is today's exported sections (`sectionRuns`), and with `grid: 1` or `2` it is the rows read through `mappedSlideGroups` in `slide-group-keys.ts`. There, a row a person made, or moved whole, becomes a slide group and so does the rest below it, a section-start row keeps its section wherever it went, and a row that only wrapped dissolves. `foldGrid` tags each row head (`retag`, carried to the first slide that stayed, else the first that moved, else what that slide headed before, else a fresh `n<i>`), and the first `grid: 3` command fixes the slide groups it computes as its heads. `OpenNoSections`, `FirstVersionThree`, `RowsNoSections` and `ThreeKeepsMadeRows` publish an empty section list and land the first version three command on default rows and on a row a person made. `ThreeAfterTwo` lands it after version two, where a packed section becomes its own slide group. `GroupsFixed` pins the heads it fixes. `OldCommandMeaning` says an older command after a version three command lands with its version three meaning or is refused: a move after an anchor and a whole slide group moved first land; a new row below an anchor is refused (`groupPlaced` in `applySlide`, since its place depended on how far the old row reached), so is part of a slide group moved whole (`groupRefusal`) and an undo whose head bits no longer match (`turnRefusal`), and an undo whose head bits still match lands. The replay checks `slideGroups` equals `gridGroups` once a log holds version three. `slide-groups.property.test.ts` generates mixed version traces and checks a partition, unique keys, that an untouched deck is its sections, that a log from before Grid is `foldSections`, and that each accepted older command after version three gives the version three result. A planted removal of `groupPlaced` failed the replay on `RefuseOldNewRow`; a planted switch that kept the row heads failed it at `ThreeAfterTwo`; a planted model move that dropped a head violated `OldCommandMeaning`. All three were removed. Leaves out: names, which come from the file by key and are tested in `slide-groups.test.ts`.

Grid, export, the agent read and the slide number control now read `slideGroups`, and `gridCommandVersion` plans every new command at version three once the section starts are known (an empty list counts), so the replay's version one and two paths are logs written before that. A person's Undo of a Grid edit is planned at the version its edit was: `gridUndoable` records it as `grid` and `turnCommands` writes it on the turn, where it used to write the register's current version. A planted turn written at version three failed the replay on an older Undo (`undo refused`). The model has no keys, so key choice is unit-tested: `mappedSlideGroups` gives a row a person made where a real file section starts that section's key, so the part holding the section's first slide keeps its name, and the rest of the section below is unnamed (`slide-groups.test.ts`); a planted removal failed that test and the export test that a regrouped deck whose slide groups equal the file's sections writes the original bytes (`grid-export.test.ts`). `sectionRuns` finds a moved slide's neighbour from the spots it folds so far instead of folding each prefix again, which made `slideGroups` on a 975-command version two log take 59 ms instead of 4.6 s; 3,000 random logs gave the same runs as the old function.
