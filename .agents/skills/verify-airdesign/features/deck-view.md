# Deck view

A deck shown outside the editor, in a browser tab or inside a chat as an MCP App: the chosen slide fit to the window and always the largest thing on the page, header controls for stepping when there is more than one slide, a thin strip of thumbnails over 480 px wide, and `Open in AirDesign`. It only shows; nothing edits. In a chat a person can pick a slide and click layers, and the view tells the model what they picked. It follows the deck like an editor tab, so it holds a painter lease and answers an agent's `screenshot()` with the editor's painter.

## Sub-features

- `show` `apps/web/src/deck-view/deck-view.tsx`: the deck's name, `Open in AirDesign` (a new tab on `/s/<id>`), the slide (`[data-view-slide]`), and the strip (`nav "Slides"`, `[data-view-thumb]`). The header buttons step one slide at a time. Left, Right, Home and End work from the stage and controls. Keyboard steps from the strip also move focus to the new thumbnail.
- `follow` `apps/web/src/deck-view/use-view-deck.ts` opens the deck with memory storage and follows it with `/doom/since`, so an agent's edit paints at once and the held catch-up is the painter lease.
- `screenshots` the view uses the editor's `useSlideScreenshots` and `useAssetUrls` from `apps/web/src/editing/`, so the same painter produces both JPEGs.
- `missing` a deck that does not open, or one deleted while shown, says Deck not found with `Go to your decks`.
- `chat` the MCP App. `packages/mcp/src/deck-view.ts` serves `ui://airdesign/deck.html`, a shell that names the API's public origin in `<html data-origin>` and loads this page's tags from `/deck-view` by absolute URLs, with no `<base>`, since hosts such as Claude send `base-uri 'none'` or `'self'`. If that fetch fails it says "AirDesign couldn't load this deck. Try again in a moment." The links resolve against `data-origin` and served fonts against the code's own URL (`fetchServed` in `packages/render`). The server advertises `io.modelcontextprotocol/ui` whenever it serves the view: to every 2025-11-25 client, whose later requests carry no capabilities, and to a 2026-07-28 client that announces the extension; `_meta.ui.resourceUri` links `airdesign_execute` and `airdesign_get_app_state` to it, and four app-only tools (`viewTools` in the catalog) answer it: open, since and screenshots carry the same doom wire as `/doom/*`, and media answers an image's bytes, base64 in `structuredContent`, for a deck the account owns. `apps/web/src/deck-view/chat-host.ts` speaks `ui/initialize` and shows the deck the call names (input `deck`, answer `deck`, `openDeck`, else the newest listed), on the slide its `screenshots` names; `chat-remote.ts` follows the deck through the view tools, so the held `since` (25 s, `viewHold`) is the painter lease.
- `host chrome` in chat, the header, backdrop and filmstrip use the host's light or dark colors and the theme's fallbacks. The slide is painted in the deck's own colors. Fullscreen is offered when the host supports it. It respects all four safe area insets, and Escape returns to inline before it can clear a selection.
- `images` in a chat, `chatAssets` in `chat-remote.ts` reads each image with `airdesign_view_media` and paints it from a `data:` URL, because the MCP Apps CSP allows `data:` in `img-src` but not `blob:`, and allows neither in `connect-src`; the capture keeps `data:` URLs as they are, so the agent's screenshot holds the image. The tab and the editor keep `deviceAssets`: `/decks/media` with the cookie, then a `blob:` URL.
- `select` in a chat only (`Shell.tellModel`): a click on the slide selects the top layer under the pointer with the editor's hit test (`apps/web/src/editing/hit-test.ts`), Shift adds or removes, a click on empty room clears. Hover draws a 1 px outline (`[data-view-hover]`), a selected layer 2 px (`[data-view-selected="<id>"]`). A chip beneath the slide names the layer or shows the count. Clear, Escape in inline mode or picking a slide clears the selection and updates the model.
- `context` after each pick of a slide or layer, `chat-host.ts` sends `ui/update-model-context` (only to a host whose `hostCapabilities.updateModelContext` is set, and never the same message twice): one line, "In the AirDesign deck view the person is on slide 2 (<slide>) of deck <deck> and has selected layer <id>.", and the same fields as `structuredContent`. Only a person's pick sends it, so a new view opening under the next call does not wipe what the person chose.
- `opening` an agent's `screenshot()` waits up to 5 s (`viewOpening`) for a painter when the account's chat showed the view in the last 30 minutes (`viewMemory`), so the view its own call opens can answer; other accounts get no painter at once.
- `bundle` its own Vite input, `apps/web/deck-view.html`, entry `apps/web/src/deck-view-main.tsx`. `tests/browser/deck-view-bundle.spec.ts` holds its first-load JS at 262 000 bytes gzip (229 204 on the host lifecycle base, 2026-11-28) and keeps text shaping lazy.

## How to get to it (user POV)

- `/deck-view.html?deck=<id>` while signed in.
- In a chat host that renders MCP Apps (Claude, ChatGPT, VS Code, Cursor): any `airdesign_execute` or `airdesign_get_app_state` call shows it under the call.

## Driving it with verify-airdesign

- **Journey.** `deck-view`: the editor answers an agent's screenshot; the agent marks and unmarks the slide so the server holds no picture at its key; the editor closes and the view opens (capture `deck-view`); the agent asks again and the view answers. The journey logs whether the JPEGs are byte-identical and asserts a mean pixel difference below 0.5 on the 0–255 scale. Then it resizes to 300, 480, 640, 736, 1024, 1470 and 2940 px wide (captures `deck-view-<width>`) and checks the slide fills its room, every thumbnail is under half the slide's width and 48 px tall, and the header steps slides at 300 px while the strip is hidden.
- **Journey in a chat.** `chat-deck-view` plays a strict chat host. A host page on one origin frames the shell, read from `/mcp` `resources/read`, from a sandbox on another origin (`localhost` against the stack's `127.0.0.1`), with `sandbox="allow-scripts allow-same-origin"` and the HTTP policy `default-src 'none'; base-uri 'none'; script-src 'unsafe-inline' 'wasm-unsafe-eval' <origin>; style-src 'unsafe-inline' <origin>; img-src data: <origin>; font-src <origin>; connect-src <origin>`, built from `_meta.ui.csp`. Its bridge answers `ui/initialize`, sends the call's tool-input and tool-result, forwards the view's `tools/call` to `/mcp` with the host's own bearer, and records `ui/open-link`, `ui/update-model-context` and `ui/notifications/size-changed`. The browser holds no AirDesign cookie. Pass: execute `createDeck` shows the new deck (capture `chat-view-new-deck`); an outside agent's slide with a picture from `images.verify.test` paints from a `data:` URL after `airdesign_view_media` (capture `chat-view-built`); the agent's `screenshot()` is answered by the view with one JPEG whose picture reads blue sky and yellow sun at their places; a click on the Growth bar sends exactly one `ui/update-model-context` naming slide 1 and that layer (capture `chat-view-selected`); `Open in AirDesign` sends `ui/open-link` with `<origin>/s/<id>`. Any `securitypolicyviolation`, console error, refusal or CORS line in any frame fails it at once with that line, except a refused `eval` the code catches, which is zod's `Function("")` feature probe. A `<base>` put back in the shell fails it in under 2 s with the `base-uri 'none'` line, and a policy without `'wasm-unsafe-eval'` fails it with the WebAssembly refusal.
- **Navigation in a chat.** The same journey checks that Previous and Next step with the strip hidden at 300 px. At 736 px it compares light and dark slide pixels and checks dark title and counter contrast with the host palette and with the fallback palette. It presses the slide keys after a click on the canvas, enters 1470 px fullscreen, checks the insets, exits with Escape, clears with the next press, and drives both sides of the toggle. Five header clicks must reach a frame with the destination slide and its fonts ready at a median of 50 ms or less.
- **States for look.** `deck-view` shows two slides in a browser with the second chosen. `deck-view-chat-narrow`, `deck-view-chat-light`, `deck-view-chat-dark` and `deck-view-chat-fullscreen` show the same chat deck at 300, 736 light, 736 dark and 1470 px with a selected layer.

## Gotchas

- Text shaping compiles WebAssembly (HarfBuzz, ICU), so a host whose `script-src` allows neither `'wasm-unsafe-eval'` nor `'unsafe-eval'` cannot shape text in the view. Claude's policy allows `'unsafe-eval'`; `chat-deck-view` allows only `'wasm-unsafe-eval'`, the narrower of the two.
- In a chat the view has no AirDesign cookie: it reads the deck only through the view tools, fonts and code come from the public origin with `Access-Control-Allow-Origin: *` (`apps/web/public/_headers`, the font routes), and images come through `airdesign_view_media`.
- The view counts as an open tab for `get_app_state`, since it follows the deck the same way.
- A screenshot the server already holds at the slide's key is not painted again, so a journey that compares two painters must change the slide between them.
