# Auto layout frames

On an open deck, Shift+A (or Add auto layout in the element's menu) wraps the selected layers in an auto layout frame: a group whose bottom layer, the backdrop, holds the frame's fill, border and corners. The frame lays its children out in a row or a column, guessed from how they sit, a gap apart, and hugs them. Its slides-mode panel is Figma's: Auto layout frame, Remove auto layout, Fill, Opacity, Corners, Border, Shadow, Selection colors.

## Sub-features

- `wrap` Shift+A sends one `element-group` slide command with a `backdrop` and the guessed `layout` as the group's opening. The status reads `Added auto layout`; the frame is selected; Undo add auto layout puts every layer back with the backdrop gone.
- `frame-paint` Fill, Corners and Border write rows on the backdrop; Shadow writes the group's effects. A click on the backdrop selects the frame.
- `frame-opacity` Opacity writes one `layout.opacity` row on the frame, and the canvas fades the frame and everything in it as one picture (`[data-group-effects]` with CSS opacity). The download multiplies it into the alpha of the backdrop and of every child, so in PowerPoint each layer fades on its own and a filled frame shows faintly through an opaque child. The editor's own paint is not multiplied. A re-imported faded frame reads each layer's alpha as PowerPoint shows it, with the frame at 100%.
- `remove` Remove auto layout writes `layout.flow: none` and each child's place relative to the frame, so nothing moves, and the title reads Frame. Its Undo brings auto layout back.
- `free-children` in a frame without auto layout, the second click selects a child, which moves and resizes on its own; its box is stored relative to the frame, so moving the frame carries it. A frame moves and resizes without scaling its children. Shift+A on a frame without auto layout lays its children out again with a gap and alignment guessed from where they sit.
- `members` a layer dropped onto a frame joins it (in an auto layout frame, at the place in the row where it was dropped); a child dropped outside its frame leaves it; a child dragged along its row moves to that place. Each is one `element-join` slide command, with box rows where the stored place changes meaning, and one undo step. Delete removes a child chosen inside its frame, and the row closes up.
- `growing-text` a text child set to Resize shape to fit text grows and shrinks with its text once its text was edited here, and the editor writes its measured height back as one `box.h` row that guards nothing against a running agent, so the next children move and the server and the export hold the new place. Not an undo step of its own. A child nobody edited only grows, so opening a file writes nothing.
- `agent-measure` an agent's row that changes a child's text, body or width owes a measure (`measureOwed`). The open tab answers it with a `box.h` row even when the height is the same, painting other slides off-screen (`[data-measure-paint]`) to measure them. An agent's next tool call waits up to 5 s for the measure while a tab follows the deck (a watch held or ended under 10 s ago), so its read shows the frame laid out as the person sees it. With no tab open it answers at once with the heights last measured. After run Undo the next read is not waited for; the tab shrinks the child a moment later.
- `design-section` design mode's Auto layout section sets Direction (Horizontal or Vertical), Gap between items, Padding on each side and Alignment, each one `layout` row on the frame; the canvas lays the children out again at once, for a frame made here or read from a file.
- `nested` a frame sits inside an auto layout frame. Shift+A on a selection holding a frame, or on one auto layout frame, wraps it in a new auto layout frame that hugs it; a frame dropped on an auto layout frame joins its flow, in the innermost frame under the pointer; a frame never joins itself or a frame inside it. Shift+A on children of a frame (picked inside it, Shift+click for more) wraps them in a new auto layout frame inside it, in the flow where the first of them was, every layer staying where it showed; its Undo puts them back in the parent's flow, and an agent's `op: frame` on children does the same. The inner frame lays out where the outer one puts it and at the size it hugs, so a gap, direction or child change inside moves the outer frame's next children. Remove auto layout and Ungroup keep every layer where it shows, and a faded outer frame multiplies into the inner frame's layers in the export. The export writes the inner frame's group inside the outer one, each with its tag, and re-import reads both back. A click picks the outer frame and each double-click steps one level in: the inner frame, then its layer; the layers panel reaches it too. Dragging the inner frame inside a frame without auto layout carries its layers as it moves.
- `sizing` an auto layout frame's Width and Height each hug its children or are Fixed, from the menus under Direction in the Design panel, which show Hug or Fixed and list Hug contents, Fixed width and Fixed height. A new frame hugs. Dragging a side handle of a hugging frame makes that side Fixed at the new size in the same undo step, and while the handle is dragged the frame lays its layers out live, from the same rows the drop commits: a filling layer stretches and a centred row recentres before the drop; Alignment then places the row along a Fixed side and across it. Choosing Fixed keeps the hugged size, and Hug shrinks the frame back. An agent sets `layout.width` or `layout.height`, and a `box.w` or `box.h` makes that side Fixed. The export writes the laid-out places and the tag keeps each Fixed side, so re-import reads it back. Proved by `tests/browser/frame-sizing.spec.ts` and the `frame-sizing` PowerPoint case; look state `frame-fixed`.
- `fill` a layer inside an auto layout frame has its own Width and Height menus in a Resizing section above Position and size: Fixed width or Fill container, and a frame inside one also has Hug contents. A layer set to Fill container takes the frame's free length along the flow, shared equally with other filling layers, and the frame's whole inner thickness across, inside its padding; the frame's backdrop never fills. Choosing Fill on a side the frame hugs makes that frame side Fixed at its size in the same step, as Figma does. An agent sets `layout.width` or `layout.height` to `fill` on the layer and starts its run with the frame too. The export writes the laid-out sizes and the frame's tag lists which layers fill (`l=5:wh`), so re-import reads it back. Proved by `tests/browser/frame-fill.spec.ts`, the `frame-fill` PowerPoint case and `packages/pptx/src/frame-fill-route.test.ts`; look state `frame-auto-child`.
- `text-fill` a text layer set to Fill container wraps at the width the frame gives it and hugs its lines as its Resize shape to fit text says; while the frame's side handle is dragged, the canvas lays the frame out again each time a measured height lands, so the next layers follow the growing text and the frame's outline and size pill show its hug height. A side the handle does not move keeps its sizing, so a hugging height stays Hug. Proved by `tests/browser/frame-text-fill.spec.ts`.
- `child-resize` a layer inside an auto layout frame shows side and corner handles (no rotate handle). Dragging one resizes the layer; its row and a hugging frame reflow live and on the drop, and the drop writes only the layer's width and height (the frame places it) in one Undo resize step. Dragging a side that was Fill container makes it Fixed, as Figma does. A frame's backdrop always paints at the frame's own box. Proved by `tests/browser/frame-child-resize.spec.ts`.
- `agents` an agent sends `op: frame` to wrap layers, `op: join` (the frame first) to add layers to its end, `op: leave` to take children out where they show, and `set` with `layout` to change the frame. A frame's `fills`, `border` and `geometry` land on its backdrop; its `opacity` lands on the frame and reads as `opacity 50` in its design line. `read_deck` marks a frame with `frame: auto` or `free`, gives every child its slide place, and leaves the backdrop out. Moving a child of an auto layout frame is refused with `group-box`; a child of a frame without auto layout moves to the slide point named.
- `export` the export writes a `p:grpSp` named Frame with the backdrop `p:sp` first and every child at its laid-out place, child space equal to slide space, and a PowerPoint tag `AIRDESIGN_LAYOUT` (in `ppt/tags/`) with the layout fields, the flow order and a seal of the places. On import the tag reads back as the same frame; a frame whose shapes moved in PowerPoint reads as a frame without auto layout, a scaled group or a lost backdrop as a plain group. An untouched frame is not rewritten.

## How to get to it (user POV)

- An open deck `/deck/<id>`: click a layer, Shift+click another, press Shift+A, or right-click and pick Add auto layout.
- `Undo add auto layout` and `Undo remove auto layout` in the toolbar.

## Driving it with verify-airdesign

Preconditions:

- `$V doctor <run>` is ok.

- **Run it.** `$V journey <run> auto-layout-frame`. Prints `"passed":true`.
- **Wrap.** A blank deck, `Rectangle` then `Ellipse` dragged to its right, both chosen, Shift+A. Evidence `NN-wrapped`; `deckRoutes.open` ends with an `element-group` row with a `backdrop`; the ellipse sits beside the rectangle, top aligned.
- **Fill, remove, undo.** Fill Solid lands a fills row on the backdrop (`NN-frame-filled`); Remove auto layout keeps both places (`NN-auto-layout-removed`); its Undo, then Undo fill and Undo add auto layout (`NN-wrap-undone`), then Redo.
- **Reload, export, reimport.** Evidence `auto-layout-frame.pptx` and `NN-reimported`: the frame paints where it was, and selecting it shows Auto layout frame (its tag read back).
- **Frame without auto layout.** Back on the deck: Remove auto layout, a second click on the ellipse, a drag 90 px up (`NN-child-moved-in-frame`); the stored box is relative to the frame. Shift+A on the frame lays it back in the row (`NN-auto-layout-again`).
- **Members.** A triangle dragged between the two children joins the row (`NN-joined-frame`; `deckRoutes.open` ends with `element-join`); Delete on it closes the row (`NN-child-deleted`).
- **Agent read.** `$V journey <run> auto-layout-measure`: two growing cards wrapped in a column; an agent sets the top card to a long line over MCP and its very next `read_deck` gives the top card's new height and the next card moved by the same amount, equal to what the canvas paints; the export holds both; Undo of the run lays the next card back.
- **Nested.** `$V journey <run> auto-layout-nested`: a square and a circle wrapped with Shift+A, that frame and a triangle wrapped again (`NN-nested`, a column holding the row and the triangle); the inner frame picked in the layers panel turns Vertical and the triangle moves down (`NN-inner-made-vertical`), Undo and Redo; a diamond dropped between the square and the circle joins the inner frame (`NN-joined-inner-frame`); reload, export and re-import keep both frames.
- **Growing text.** `$V journey <run> auto-layout-text`: two growing text boxes wrapped in a column; three more lines typed into the top one push the bottom one down, and `deckRoutes.open` holds a `box.h` row on the top one.
- **Opacity.** `$V journey <run> auto-layout-opacity` (and `tests/browser/frame-opacity.spec.ts`): `frame.pptx`, the frame's Opacity set to 50 fades the group layer to 0.5 with every child's own fill unchanged; Undo opacity, Redo, reload; the export writes `alpha 50000` on the backdrop and both children.
- **Design mode and Aira.** `$V journey <run> auto-layout-agent`: the fixture `frame.pptx` opens as an auto layout frame; design mode's Auto layout section reads Horizontal (`NN-auto-layout-section`) and Vertical stacks the children (`NN-made-vertical`). Aira's recorded `frame-layout.sse` sets the frame back to a row with a 24 pt gap and a teal fill, which lands on the backdrop as the agent's row (`NN-aira-row-teal`); the panel's Undo brings the column back (`NN-aira-undone`).
- **States for look.** `panel-frame`, `panel-frame-design`, `frame-nested`, `frame-wrapped-inside`.

## Gotchas

- `deckRoutes.open` can lag the status line by a moment: poll it for the `element-group` row, as the journey does.
- Shift+A guesses the direction from how the layers lie: drag the second shape beside the first for a row, under it for a column.
- A re-imported deck opens with the Agent panel, so open Design before comparing places with the ones measured beside the Design panel.
