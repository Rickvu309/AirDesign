# Stand-ins

The stack's only stand-ins are the mail sender (writes a file instead of calling Resend), the original store (in memory instead of R2, its signed URLs served by the front server under `/verify-original/`), Aira's model (`bin/scripted-aira.mjs` plays recorded streams instead of calling Claude, unless `launch --model-key-env <NAME>` gives the stack the real model with the key read from that variable; `--model` and `--effort` change only that stack's Aira, and the launch line and `proof.md` name what it uses, never the key), the country header (the front server adds `visitor-country: US` as the web worker would from Cloudflare's `request.cf.country`), the image fetch (an agent's image address on `images.verify.test` answers with the file of that name in `tests/browser/fixtures/`, and every other address goes to the real fetch with its guards, through the API's `imageNet` seam), and production pages (the journey kit answers any `airdesign.app` address, such as the sign-in redirect, with a stand-in page). Each sits behind a production seam. The stack sends no forward secret, so the API's forward-secret check is not exercised.
