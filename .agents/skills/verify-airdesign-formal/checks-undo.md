# Checks on a person's own Undo and Redo

Same fields as [checks-document.md](checks-document.md). person-undo is replayed in `tests/spec-replay.test.ts`; typing in `apps/web/src/typing.test.tsx`, which renders the editor's undo parts in jsdom: `pnpm vitest run apps/web/src/typing.test.tsx`. The undo of an added or removed element is element in [checks-document.md](checks-document.md), and a run's own Undo is undo there and slide-undo in [checks-slides.md](checks-slides.md).

## person-undo

A person's Undo and Redo of their own text edit, beside an agent run.

- `UndoShowsBefore`: an undo or redo shows exactly the text it went back to.
- `NeverCoversAgent`, `AgentRowStays`: a person's undo never lands over an agent row that shows, and only the run's own Undo hides that row. Harm: a person's Ctrl+Z erases Aira's work.
- `DroppedIsTold`: an undo that changed nothing is always told.

Bounds: up to four person rows, one agent row. Run: `pnpm check:specs person-undo`. Replay: `tests/person-undo-replay.ts` through `undoOf`, `redoOf` and `decide`. Code: `undoOf`, `redoOf` in `packages/document/src/person-undo.ts`, the stack in `apps/web/src/undo-list.ts`. Leaves out: box undo, slide undo (`slideUndoable`) and notes edits, which take the same path as text. The undo of an added or removed element, with another tab and an agent's run in between, is covered by element. An undo while typed edits are still being recorded or sent, and the browser's own undo, are typing.

## typing

A person types two letters of speaker notes, then two over a text box, and presses Ctrl+Z, later Ctrl+Shift+Z, while what they typed is still on its way. Each edit is written to the device at once. A keystroke's undo record lands once the device answers and the session's text before is read (`editText` in `apps/web/src/editor/editable-slide.tsx`); a notes edit's lands in the task the device's answer comes in (`useNotes` in `apps/web/src/notes-edit.ts`), and neither waits for the server. Each edit then goes to the server, and the box stays busy until its keystrokes got there. A text is a number: 0 the text before the typing session, 1 its first letter, 2 the whole new text. The undo list is a number whose digits are its entries (1 and 2 the notes, 3 and 4 the box), because the graph reader takes only plain values.

- `UndoRestoresBefore`: one undo after typing holds and shows, in the element it turned, the text from before the typing session, never a part of the new text. Harm if broken: Ctrl+Z straight after typing "New" over "Old" shows "N", PR 427's fault.
- `NeverPartOfNew`: once the whole new text is typed, the box never shows only its first letter.
- `NoUndoOnMissing`: an undo or redo never reads a list that is missing a record already typed. The ghost `missing` is set when the undo reads the list (`Turn`).
- `TurnLands`: every undo and redo asked for after typing lands. Harm if broken: Ctrl+Z straight after typing does nothing, or says nothing changed.
- `ShownIsDeck`: after an undo or redo, the box and the notes show what the deck holds. Harm if broken: the box keeps the typed text while the deck went back.
- `RedoRestoresTyped`: a redo brings back the whole typed text.
- `UndoTakesLastTyped`: the element one undo turns is the one the person typed in last. Harm if broken: on a slow network the first Ctrl+Z after typing over a text undoes the speaker notes instead, the fault from `3b0c63e1` that PR 441 pinned.

Bounds: one box with two keystrokes, one slide's notes with two edits typed before the box, one undo, then one redo, no typing after the first Ctrl+Z. 248 states, 568 edges. Run: `pnpm check:specs typing`. Replay: `apps/web/src/typing.test.tsx` renders the real `Passage`, `useUndoList`, `useUndoTurn` (with its `useUndoKeys`) and `useNotes` in jsdom over a real paint store and the parts of `scripts/pptx-fixtures/clean.pptx`, and takes all 568 edges in 175 walks from the start. So the undo's own waits, `turnBack`, `showTurned`, the repaint as the person and `notesShown` are the product's, through `recordsInFlight`, `recorded`, `liveRepaint`, `busyElements`, `showText`, `commitEdit`, and `decide`, `undoOf` and `redoOf` on a register. The device (`connect`) is a stand-in: a write lands on the register at once, its answer waits for the model's `RecordNotes` or `RecordText`, its upload for `UploadNotes` or `UploadText`, and the undo's deck read for `Turn`. After every step the test compares every model variable with the code (the box's text in the DOM, the notes shown, the deck, the undo and redo lists, the counts), checks the box is busy exactly while a keystroke is unsent, and checks the undo reaches its deck read exactly when the model's waits are met. `KeyUndo` and `KeyRedo` press the keys on the box, or on the page when only notes were typed, and check the browser never gets them; `MenuUndo` sends `historyUndo` and checks the box refuses it. Code: `recordsInFlight`, `recorded`, `turnBack` in `apps/web/src/undo-list.ts`, `liveRepaint` and `busyElements` in `apps/web/src/live-repaint.ts`, `useNotes` in `apps/web/src/notes-edit.ts`, `undoKey` and `useUndoKeys` in `apps/web/src/editor/undo-keys.ts`, the `beforeinput` refusal in `packages/render/src/passage.tsx`, `turn` and `showTurned` in `useUndoTurn` in `apps/web/src/editor/use-undo.ts`, and `editText` in `apps/web/src/editor/editable-slide.tsx`.

Leaves out: the replay restates `editText` instead of driving it, since `editableSlide` needs a painted deck: it holds the box and the records, reads the text before at the session's start and records in the paint step. `tests/browser/person-undo.spec.ts` drives it in a browser. The model takes the text before as read from the device before the first keystroke's write lands. They are two IndexedDB transactions in `packages/live`, and IndexedDB runs them in the order they were created; the read's is created first only because `openDeck` reaches `heldView` in as many awaits as `enqueue` reaches `changeHeld`, and `editText` asks for the read first. `packages/live/src/cache-order.test.ts` holds the read on the device while the write is asked for and fails if one more await flips them. It takes the device as answering writes in typing order, and a notes edit as recording in the task its answer comes in, so a keystroke records after every notes edit typed before it (`RecordText`). Uploads finish in any order in the model; the device sends them one at a time in call order (`serial` in `packages/live/src/cache.ts`). Also left out: typing after Ctrl+Z, notes typed after the box, a second undo, Ctrl+Z inside the notes field (a form field, so the browser's own undo of the field), boxes, slides, tables and added elements, the server's answers that repaint (`reconcile`), and agent runs (person-undo). A table's cell edits read the deck and write it one at a time (`onTable` in `apps/web/src/table-hook.tsx`); the next one waits only until the one before is kept and recorded, never for its upload, which `apps/web/src/table-hook.test.tsx` checks. Slide commands, added and removed elements, pictures and box moves record once the device answers and before they go to the server.
