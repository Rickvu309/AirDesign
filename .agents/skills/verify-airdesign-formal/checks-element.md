# Checks on adding and removing an element

Same fields as [checks-document.md](checks-document.md). element is replayed in `tests/spec-replay.test.ts` through `tests/element-replay.ts`.

## element

A text box, a shape, a table or a picture a person adds, types in and removes, the person's Undo and Redo of the add or the removal, another tab removing it or bringing it back in between, another agent's run writing in the text box and the person's Undo of that run, an agent's run that adds a text box or removes the element with the run's Undo, the picture's bytes reaching the server, and an export of the deck on another device.

- `RemovedWasAdded`, `TypedWhileShown`, `TraitTakenByKind`, `UploadedWasAdded` are guards of the model. The promise lives in the replay: after a remove, add, type and remove of that id are refused, a restore of an element that shows is refused, and `nextElementId` never hands an added id out again, for a person and for `add_text_box`. It also never hands out any id the slide named before, in its file, a copied slide or any edit, so a group someone ungrouped never lends its id to a new layer (`apps/web/src/editor/group-actions.test.ts`). Harm: a deleted text box, shape or picture takes edits or its id is reused, and every add on that slide is refused.
- `UndoShowsBefore`: an undo shows whether the element showed before the person's add or removal, and a redo shows the edit again. Harm: Ctrl+Z after adding a box, a shape or a picture leaves it, or after deleting one leaves it gone.
- `DroppedIsTold`: an undo or redo after someone else changed whether the element shows changes nothing and is told. Harm: a person's undo removes a box another tab brought back.
- `UndoKeepsAgentRow`: a person's Undo of an add, or Redo of a removal, never takes away a box that shows an agent's row written since the person's edit. Such a turn lands only while the box shows what the person's edit left (`Kept`); anything else is told, as `DroppedIsTold` says. Harm: Ctrl+Z after adding a text box deletes the text an agent wrote in it. `AgentWroteText` is a guard of the model.
- `RunUndoRestores`, `RunUndoOnlyUnchanged`, `RunUndoOnce`: a run's Undo leaves the element as it was before the run (gone after an add, back after a removal), and lands only while the element still shows as the run left it, no person typed in a box the run added, and no one but the run removed or brought back the element since the run's row (`fenced`). The run's own Undo counts, so it lands once. Anything else is refused `run-fenced`, and nothing changes. Harm: Undo of an agent's run deletes text a person typed, or brings back an element a person removed, even one they removed again after the run's first Undo brought it back.
- The replay also drives `AgentRemoveRefused`: an agent's `delete_element` on a box a person typed in after the run added it is refused `person-protected`. It and `UndoRunRefused` change nothing in the model; the replay checks that the code refuses them.
- `ExportHasBytes`: a deck with a picture exports on another device only once the picture's bytes uploaded. The replay checks that `addedPictures` lists the picture's hash in every state that holds it, so the editor's export check (`missingPictures`, `exportablePictures` in `apps/web`) refuses while the bytes are missing. An export reflects the deck at that moment, so every later step clears `exported`. Harm: another device writes a PowerPoint file whose picture points at a missing media part.

Bounds: one element on one slide, one undo entry, one agent run that adds, removes, or adds and removes, one picture's bytes, and one other run that writes once in a text box no one typed in yet, which someone may type over after. That run never shares the model with the run that adds or removes. `Type` is typing this one undo entry does not cover: another tab or person, or this person's own step, which sits above the add in their undo list and is undone first. Exports are modelled only for a deck whose element is a picture, or before anything was added, since only a picture's bytes hold an export back. 473 states. Run: `pnpm check:specs element`. Replay: `tests/element-replay.ts` reaches every state through the code (`call("commit_edits")`, `call("add_text_box")`, `call("delete_element")`, `call("undo_run")`, `undoOf`, `redoOf`) and checks every edge and every forbidden action three times, with a text box, a shape without a text body and a table as the element a person's `Add` makes. `Upload` and `ExportElsewhere` change no register, so the replay checks them against `addedPictures` only. `AgentWrite` is `start_run`, `edit_deck` and `stop_run`, and `UndoWrite` is `undo_run`. Code: `elementRefusal`, `elementGone`, `nextElementId`, `addedPictures` in `packages/document/src/element-order.ts`, `slideUndoable` and `elementsUndoable` for one element, `elementsTurn` with `shownOn` and `stillShows`, and `undoableAt` with `fencedSince` in `person-undo.ts`, `shownOver` in `row.ts`, `slideMeasure` in `slide-measure.ts`, `deleteElement` in `packages/engine/src/agent-elements.ts`, `applySlide` in `slide-order.ts`, the `dead` check in `decide`. A table's `Type` is one edit of its value: a typed cell and an added row, as `changedTable` in `packages/document/src/table-value.ts` writes them, and `openedTable` there decides which table an add may carry. Leaves out: other elements and other slides; the remove of a plain group whose last layer a join took out (`groupEmptied` in `elementRefusal`), which structure models; a copy of a group, frame or layer inside a group, whose `element-clone` carries its `layers`, whose Undo removes the copy and so every layer in it (`elementGone`), and whose ids `nextElementId` counts, tested in `packages/document/src/group-clone.test.ts`, `packages/pptx/src/group-clone.test.ts` and `packages/engine/src/agent-duplicate.test.ts`; a copy pasted onto another slide, tested in `packages/document/src/element-paste.test.ts` and `packages/pptx/src/element-paste.test.ts`; a layer pasted from another deck, an `element-add` whose `pasted` carries its markup, its images' hashes (`addedPictures`) and its layers, whose Undo removes it and every layer in it (`elementGone`), and whose ids `nextElementId` counts, tested in `packages/document/src/pasted-layers.test.ts` and `packages/pptx/src/shape-carry.test.ts`; a paste to replace, whose one undo takes the copies away and brings back the layers they replaced (`swapUndoable`, with each layer's own before and after in `elementsTurn`), tested in `packages/document/src/swap-undo.test.ts`; the layout a new slide takes (`layout` and `layoutPart` on `add` change only the opening elements the command carries and the part the export points at, never an order or a refusal); the animated-shape refusal (`locked`), which depends on the index (`packages/engine/src/agent-elements.test.ts`, `packages/document/src/element-order.test.ts`); where a new text box, table or picture lands (`placeNewBox`, tested in `packages/document/src/box-placement.test.ts`); the table value's own rules (rows, cells, `from`), which `table-value.test.ts` covers; the upload itself (`flushMedia` in `packages/live`, `/decks/media/upload` in `apps/api`), which `packages/live/src/media.test.ts` and `apps/api/src/media.test.ts` cover; and export, where `orderedParts` in `packages/pptx/src/slide-order-route.ts` applies each slide's net element change, a table through `graphicFrame.addTable` and a picture through `addPicture`, and gives a copy the elements its slide showed when it was copied (`packages/pptx/src/element-order.test.ts`). Stacking an element (`element-order`, `elementStacks` and `stackRefusal` in `packages/document/src/element-stack.ts`, and the stack branch of `turn`) changes which sibling it sits before and never whether it shows or which id comes next, so this model leaves it out. A duplicate leaves removed elements out of its copy, for an agent (`agentSlide` in `packages/engine/src/agent-slides.ts`, tested by `packages/engine/src/duplicate-removed.test.ts`) and for a person (`flooredEdit` in `apps/web/src/slide-floor.ts`, tested in `apps/web/src/slide-copy.test.ts`); no spec models the duplicate. A run's Undo of an element reads the deck's order: `fencedSince` refuses it once a row after the run's row, not of the run, removes or restores the element, and the rows the run's own Undo writes carry no run. That closed the gap where a second Undo of the same run landed again once someone brought the element back to the state the run left it in. The model folds another tab's change and the run's own Undo into the one flag `fenced`, so it leaves out the run removing a box it added after another tab removed it and brought it back, which the code lands. The second Undo still lands for a run's slide commands: an `it.fails` test in `packages/engine/src/agent-slides.test.ts` holds it, and slide-undo models no person who deletes a slide. Planted faults: `RunUndoable` without `~fenced` fails `RunUndoOnce` in 109 states (AgentAdd, OtherRemove, OtherRestore, UndoRun), and `undoableAt` without `fencedSince` lands 131 `UndoRunRefused` edges of the replay and fails three tests in `packages/engine/src/agent-elements.test.ts`. The tab decides a person's Undo on its own copy, which replays every row as a person's (`played` in `packages/live/src/deck-view.ts`), so `turn` cannot ask who wrote a row: it compares what the element shows, each field the opening or a visible row set, with what it showed right after the person's edit, and text with no characters counts as empty in any form, since the editor writes an emptied box as an empty paragraph. So a Redo of a removal is also told after the person undid an agent's run whose text showed when they removed the box, an agent that writes again exactly the text the person removed is not told apart, and an agent's row that reaches the server after the tab read its copy is not seen, as for every person Undo. A run's Undo of a box it added is refused `run-fenced` once another run's row shows in it (`packages/engine/src/agent-elements.test.ts`); the model leaves that out. `tests/browser/person-undo-elements.spec.ts` drives the add, an MCP agent's write and Ctrl+Z in the app. `TraitTakenByKind` is the admission rule: the server admits a row only on a trait field the element's kind takes, so text lands on a text box and never on a picture. `kindTraits` in `packages/document/src/traits.ts` is the one table of the traits each kind takes, and `takes` in `packages/document/src/element-takes.ts` turns it into the live fields an element takes (`removable` says which a person may delete); `decide`, `elementRefusal`, the MCP edit and delete tools and the export in `apps/web/src/exported-parts.ts` all read it. The replay checks that the code's table agrees with the model's `Takes` (`takenByKind`) and that `Type` on a picture is refused (`packages/engine/src/call.picture.test.ts` too). A drawn rectangle or ellipse holds no text body, so the replay checks that its `Type` is refused `kind` and leaves its typed states unreached. Every other kind and edit is tested in `packages/document/src/element-takes.test.ts`, not modelled.
