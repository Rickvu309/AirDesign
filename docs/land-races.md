# What `pnpm land` does with a failed unit test

When only the `unit-tests` step failed, it runs each failed file alone once. A file that fails alone too is a fault and stops the push. A file that passes alone has a race. If the branch changes that file, the push stops and says to prove the race by forcing the gap: a delay that makes the old code fail every time, then the fix passing 5 times in a row with the same delay. If the branch does not change it, the push goes on only once the race is a GitHub issue titled `Race: <file> › <test>`, with the failure output and the commit; a later failure of the same test comments on that open issue. When the test's issue is closed by a merged pull request, a failure on a commit without that pull request's merge commit comments there that it predates the fix and files nothing, and a failure on a commit with it reopens that issue (`scripts/race-issue.rule.md`).
