# AirDesign v0.1: change-log fixed points

Research date: 2026-11-03. Recommendation: server-authoritative, property-versioned JSON commands, optimistic browser overlay, durable command receipts and ordered event replay. Keep agent orchestration outside change-log. The prototype validates scalar-property semantics, not production sync.

## Findings

**Authority beats automatic merging here.** Agents need actionable refusal, and multi-property commands must be atomic. OT transforms concurrent operations, particularly text offsets; its transformation machinery adds little to independent slide properties. Figma's [multiplayer design](https://www.figma.com/blog/how-figmas-multiplayer-technology-works/) uses a central server, object/property registers, server-arrival ordering, offline reapplication and local undo. It deliberately avoids full OT/CRDT complexity. Its last-writer-wins policy alone does not implement person-wins. Treat this 2019 account as a design precedent, not a guarantee of today's internals.

**CRDTs solve convergence, not priority.** [Yjs updates](https://docs.yjs.dev/api/document-updates) are commutative, associative and idempotent; its [UndoManager](https://docs.yjs.dev/api/undo-manager) can track transaction origins. [Automerge](https://automerge.org/docs/reference/documents/conflicts/) preserves concurrent scalar alternatives and exposes a deterministic winner. [Loro maps](https://loro.dev/docs/tutorial/map) use LWW; its [movable tree](https://loro.dev/docs/tutorial/tree) and [local undo](https://www.loro.dev/docs/advanced/undo) handle richer collaborative structures. None of these documented defaults supplies role priority, arbitrary run removal and whole-command refusal together. Using one would still require an authoritative policy layer. Revisit a scoped text CRDT if concurrent character editing becomes necessary; v0.1 can treat text as one property.

## Seven enabling constraints

1. **One transactional order per deck.** Lock its head row with [SELECT FOR UPDATE](https://www.postgresql.org/docs/current/explicit-locking.html); validate, increment the deck sequence, append the accepted event, update projection/property stamps, store receipt and enqueue notification in one transaction. Test simultaneous writers and crashes before/after commit. A process semaphore alone is insufficient across server instances.
2. **Version semantic properties, fence structure.** Key by `(elementId, generation, property)`. Agent writes require exact current property versions; reject the entire batch on one mismatch. Treat related tuples such as parent/order as one property. Insert checks absence; remove checks element-wide revisions; any edit checks existence/generation. Never recycle ids without generations. Test unrelated-property acceptance, delete/edit races, cycles and ABA after undo.
3. **Specify person priority explicitly.** Universal stale refusal contradicts person-wins: agent(base=0) commits first, then person(base=0) must either lose or bypass refusal. Recommended exception: person's property writes win in server-arrival order, including own tabs/offline replay; agents retain strict version checks. Also protect person-written properties against fresh-read agents until explicit delegation. Prototype uses persistent protection without a release API. Protection lifetime needs a product decision; base versions alone cannot enforce the requested interleaving invariant.
4. **Retry identity is immutable.** Scope change ids to deck/principal; retain request hash and terminal receipt, including refusals. Same id/payload returns the original result; changed payload is an error. Re-reading/revising a refused command requires a new id. Derive actor identity from authentication, never caller assertions. Test lost ACK, duplicate delivery and id reuse.
5. **Undo is selective history, never blind inverse.** Append a run-deactivation event and recompute affected properties from retained contributions, preserving later person edits. Advance versions even for equal values; never resurrect an already undone run. Cancel/fence the run before undo. Agent-created elements later edited by the person must survive through an explicit adoption rule; report retained dependencies. Compare is read-only; slide revert is a new guarded command. Test arbitrary undo orders and insert/adopt/remove dependencies.
6. **Replay is durable and cursor-based.** Browser IndexedDB stores original command ids, bases and per-tab order before claiming an edit is saved. Keep confirmed state separate from pending overlay; consume terminal refusals and display them. [WebSocket](https://www.rfc-editor.org/rfc/rfc6455#section-5.4) orders data on a connection, not durable processing across reconnects. Use at-least-once replay with idempotent effects; apply contiguous deck sequences, deduplicate and fetch gaps. Subscribe before snapshot/high-water replay; overflow forces resync. Test disconnect at each ACK boundary.
7. **Bound the live path.** Commit means database commit, not MCP response. Push committed deltas immediately; proposed connected/visible-client budget: dispatch ≤10 ms, downstream network ≤40 ms, decode/projection ≤10 ms, next paint ≤17 ms, reserve 23 ms. These are allocations, not measurements. Trace commit-to-painted-sequence; test ≤100 ms under stated payload/load/network limits. Offline, suspended tabs and arbitrary WAN delay cannot meet an unconditional deadline. One built-in agent run per deck needs a database uniqueness constraint plus fencing token; external agents still use the same commit policy. Selection/live activity are separate expiring, per-session streams and do not advance deck versions.

## Postgres shape and risks

Use `deck_head(deck_id PK, seq, projection_jsonb)`, append-only `deck_event(deck_id, seq PK-with-deck, change_id, actor, run_id, schema_version, changes_jsonb)`, `command_receipt(deck_id, principal_id, change_id UNIQUE, request_hash, result)`, property stamps/contribution indexes, immutable `snapshot(deck_id, seq, schema_version, state, provenance)`, and transactional outbox rows. Runtime role cannot update/delete events. Snapshot state and sequence atomically; replay only later events. Keep run attribution/tombstones or archived contributions for the promised undo horizon: a JSON-only snapshot cannot support arbitrary selective undo. Notification is a wake-up hint: [Postgres NOTIFY](https://www.postgresql.org/docs/current/sql-notify.html) fires after commit, but disconnected listeners recover from the durable log. Test failover and recovery with real Postgres as well as PGLite.

Top risks: unresolved priority exceptions/protection lifetime; structural adoption semantics; snapshot compaction breaking undo; unbounded undo/replay costs; optimistic rollback flicker; short-id collisions; latency assumptions. Persist rejection receipts separately from accepted deck sequences.

## Prototype evidence

`log.ts` models two fixed elements with two scalar properties each. It implements atomic commits, property versions, person priority/protection, immutable receipts, run tagging, selective run undo and retryable offline queues. No code comments. Queue snapshots simulate reload; IndexedDB, structural insert/move/remove, RPC, Postgres/PGLite and rendering are not implemented or proven. Commands are trusted typed inputs; production RPC requires schema validation. History rebuilding is intentionally linear.

From this directory, Node 22.17.1 / npm 10.9.2:

```sh
npm run verify
```

This performs a locked clean `npm ci`, TypeScript checking and Vitest. Final run: install 916 ms; TypeScript passed; 10/10 tests passed; Vitest elapsed 4.85 s, test execution 4.13 s. These are verification timings, not a sync benchmark. Full output: [verification.txt](./verification.txt).

Each property used 5,000 generated cases, seed `20261103`, sequences of 1–80 commands, 1–4 distinct properties per commit, fresh/stale bases, three agent runs and person writes: 20,000 cases total, no failing counterexample.

| Property | Cases | Time |
| --- | ---: | ---: |
| Run undo preserves person edits and other retained contributions | 5,000 | 481 ms |
| Duplicate commit/refusal/undo has no additional effect | 5,000 | 1,824 ms |
| Arbitrary generated person/agent interleavings preserve person values | 5,000 | 856 ms |
| Offline replay, lost ACK and queue reconstruction | 5,000 | 965 ms |

Six targeted tests cover batch atomicity, independent properties, both arrival orders, own tabs, fresh-read agents, undo order, late writes, ABA, changed-payload id reuse, mutable callers and offline races. Property tests are evidence over bounded generated inputs, not exhaustive verification.

Why the scalar invariant holds by induction: a person write establishes the current protected value; a later agent batch touching that key is refused before any mutation; later person writes replace it and retain protection. Undoing an agent run excludes only that run's contributions, so the latest retained person assignment remains. Idempotency follows from checking immutable receipts before all state mutation. These arguments rely on trusted actor identity, serial execution and the prototype's permanent protection policy; they do not establish structural correctness.
