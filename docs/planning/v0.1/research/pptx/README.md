# AirDesign v0.1: PPTX fidelity fixed points

Research date: 2026-11-03. **Preservation probe: PASS; visual fidelity: unverified.** The feasible foundation is an original OPC package plus a narrow OOXML editor. Rebuilding imported decks through pptxgenjs cannot support the fidelity promise.

## Findings

**pptxgenjs versus an owned writer.** Scope these findings to upstream **4.0.1**, installed and inspected here; search results also surface forks with different capabilities. Its [public API](https://github.com/gitbrent/PptxGenJS/blob/v4.0.1/types/index.d.ts) generates presentations, with no existing-package import, opaque-part retention, or font-embedding API. It supports authored [masters and placeholders](https://gitbrent.github.io/PptxGenJS/docs/masters/), but those definitions are not an importer for arbitrary inherited master/layout/theme graphs. Its [XML generator](https://github.com/gitbrent/PptxGenJS/blob/v4.0.1/src/gen-xml.ts) emits `normAutofit` for shrink without calculating a font scale. Use it for fixtures and constrained new content. Own the import/export adapter, dependency graph, and selective writer; implementing all OOXML from scratch would vastly exceed v0.1.

**Package preservation.** [ECMA-376](https://ecma-international.org/publications-and-standards/standards/ecma-376/) separates OPC packaging, document markup, and compatibility rules. Retain original bytes by part URI, content types, relationship owners/IDs/targets, and original item XML spans. A text edit needs only its slide part; adding media also changes that owner's `.rels`, adds media, and possibly updates content types. Preserve namespace context, unknown attributes/elements, ordering, `AlternateContent`, master/layout/theme references, and IDs. Relationships belong to a part, not an item: do not regenerate a slide's relationship table from recognized shapes. Keep shared dependencies until no retained object uses them; clone before editing shared assets. Hash **uncompressed part payloads**, not serialized DOMs. ZIP offsets/compression/headers may change; whole-archive identity is a separate promise. [JSZip explicitly documents this distinction and compression reuse](https://github.com/Stuk/jszip/blob/main/documentation/limitations.md).

**Metadata.** Prefer namespaced, versioned custom XML associated through `p:custDataLst/p:custData r:id`, with owner relationships and custom XML properties/content types. [PowerPoint CustomerData](https://learn.microsoft.com/en-us/office/vba/api/powerpoint.customerdata) documents persistence in PPTX and association with shapes, slides, masters, and layouts; copying objects creates new custom XML parts. [The OOXML element](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.presentation.customerdata) provides the relationship hook. Store UUID, schema version, roles, layout constraints, brand references, and an exported semantic fingerprint. On re-import restore only when content, geometry, style, inherited dependencies, and assets still match; XML hashes alone falsely fail after PowerPoint normalization. Shape IDs alone are insufficient after copying. Re-key duplicate UUIDs. Generic extension lists have weaker application-specific retention evidence; do not assume unknown extensions survive editing. Actual Windows/Mac/web PowerPoint save/reopen tests remain required; this probe does not test metadata persistence.

**Text and fonts.** Preserve explicit breaks, paragraphs, run properties, tabs, bullets, insets, language, theme fonts, and inherited sizes. Distinguish `noAutofit`, `spAutoFit`, and `normAutofit`, retaining its [fontScale](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.normalautofit.fontscale) and line-spacing reduction. Chromium measurements cannot establish PowerPoint line-break parity. New text should use tested font binaries and conservative geometry; explicit line breaks help but do not guarantee parity. Record original and effective fallback names separately and flag substitutions. [OpenType fsType](https://learn.microsoft.com/en-us/typography/opentype/spec/os2#fstype) distinguishes restricted, preview/print, editable, and installable embedding; honor no-subsetting and bitmap-only flags plus the actual license. Preview/print permission does not authorize editable use. Preserve existing embedded parts; do not blindly convert or re-embed. [Microsoft's font-part notes](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oe376/1663dabc-5d98-463f-889e-bcd9b77c3d34) distinguish PowerPoint `application/x-fontdata` from Word's obfuscated fonts: renaming TTF to `.fntdata` is not a verified embedding implementation.

**Preview gap.** There is no universal per-item bitmap preview contract in PresentationML. [OLE objects can contain pictures](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.presentation.oleobject), but that does not establish previews for arbitrary unknown items, comments, or animations. A package thumbnail is not an item preview. Extract available fallback pictures/drawings; otherwise require a trusted render or expose a flagged unavailable preview. Animation fidelity also needs playback checks. Moving/resizing a kept item changes its wrapper/transform while retaining its payload; deletion may require updating timing references. This is not whole-item byte identity after an edit.

## Seven enabling constraints

1. **Original bytes are durable state.** JSON contains item tier plus opaque package references; `apply` stays pure, returns inverse/error, and never reconstructs the archive. Undo restores those references. No-op export hashes every original part identically, except explicit security removals and AirDesign additions.
2. **Native means tested editable coverage.** Promote supported properties only; retain unknown subtrees even inside native shapes. A one-run edit must preserve every other part and every byte outside that text span. Mixed native/kept items on one slide are mandatory fixtures.
3. **Changes declare dependency closure.** Preserve IDs and owner relationships; transforms, media replacement, shared resources, deletion, and animation references each have fixtures. No dangling targets or repair prompts. Macro removal includes payloads, relationships, and content types, always reported; external targets stay inert, are never fetched, and are always flagged.
4. **Metadata restoration is conditional.** Supported PowerPoint save/reopen and copy/paste fixtures restore untouched items, invalidate externally changed items, and resolve copied identity collisions. Metadata removal must degrade safely to ordinary import.
5. **Text fidelity has a font contract.** Pin font hashes, fallback mapping, effective run metrics, and autofit state. Test Latin/CJK/RTL, bullets, tabs, emoji, and overflow. Missing fonts always appear in the change report; embedding eligibility is checked before new embedding.
6. **PowerPoint is the visual oracle.** Export original and result with the same PowerPoint build/fonts/OS at 1920×1080 using [Slide.Export](https://learn.microsoft.com/en-us/office/vba/api/powerpoint.slide.export). Compare studio renders separately. Use LibreOffice for fast secondary regression checks, never as proof of PowerPoint parity. Proposed initial gate: `pixelmatch threshold=0.1, includeAA=false`, mismatch fraction ≤0.1% globally and ≤1% per item, plus zero changed line counts/clipping and human review. These are provisional tolerances, not proven perceptual equivalence; [pixelmatch threshold is a per-pixel difference](https://github.com/mapbox/pixelmatch), not a percentage. Same-renderer no-op fixtures should have zero mismatches. Changed-text comparisons mask only the expected edit region and still check overflow.
7. **Import is a bounded hostile-file job.** Proposed initial caps: 100 MiB ZIP input, 500 MiB actual inflated total, 10,000 parts, 8 MiB/XML, 64 MiB/binary, XML depth 128, 256 attributes/element, 500,000 XML nodes/job, expansion ratio 100:1, 30 seconds, 512 MiB worker memory. Reject duplicate/colliding/path-traversal names, encrypted archives, malformed sizes/CRC, unsupported compression, and ZIP64 initially. Enforce actual streamed bytes, not only directory claims; reject DTD/entities, disable XInclude/resolvers/network, and never recursively unpack embeds. [yauzl](https://github.com/thejoshwolfe/yauzl) supports lazy entries and size validation; [OWASP](https://cheatsheetseries.owasp.org/cheatsheets/XML_External_Entity_Prevention_Cheat_Sheet.html) explains XML entity defenses. A killable process/container must also isolate font/image decoders and LibreOffice. Caps are product policy, requiring corpus tuning and adversarial tests.

## Libraries and architecture

Use yauzl for bounded streaming reads, [yazl](https://github.com/thejoshwolfe/yazl) for output, a namespace-aware parser plus original source spans for surgical patches, Node crypto for SHA-256, and pixelmatch/pngjs for comparisons. JSZip is sufficient for this trusted fixture, not the hostile-file boundary. The probe uses [saxes](https://github.com/lddubeau/saxes), which does not resolve DTD entities but is archived; production adoption needs a maintenance decision. Vitest/fast-check should exercise edit/inverse, graph integrity, and malicious packages. The fixture pins an `image-size` override to 2.0.4; clean install audits zero known vulnerabilities.

T3 reference inspected at checkout [cefb544af3c98224874419198c0359b652ca3c94](https://github.com/pingdotgg/t3code/commit/cefb544af3c98224874419198c0359b652ca3c94): thin transports, a service boundary and schema-derived contracts transfer well. Expose one PPTX service to studio and MCP; keep package I/O in the adapter and JSON changes pure. AirDesign needs no provider/harness machinery.

## Reproduction and measured result

From this directory, Node 22.17.1/npm 10.9.2, exact clean-install command run:

```sh
mkdir -p .tmp && TMPDIR="$PWD/.tmp" npm ci --ignore-scripts && TMPDIR="$PWD/.tmp" npm run verify
```

Type checking and assertions pass. Two-slide fixture: **26 parts, 25 identical, only `ppt/slides/slide1.xml` changed**; UTF-8 bytes outside the edited run also identical, including its sibling shape and second run. Both output files are reopened with CRC checks. Four parser rejection cases pass. [report.json](output/report.json), [hashes.json](output/hashes.json), [shapes.json](output/shapes.json), [before.pptx](output/before.pptx), [after.pptx](output/after.pptx) contain evidence.

Single-run milliseconds: generate 21.704; unzip 3.104; parse 2.144; patch 0.826; rezip 18.912; reopen/hash/compare 20.655. Archive sizes: 52,589 → 17,655 bytes. Timings describe a tiny warm local fixture, not throughput or speedup; differing ZIP compression explains archive-size differences without payload changes.

`command -v soffice` found `/opt/homebrew/bin/soffice`; `soffice --version` failed because `/Applications/LibreOffice.app/Contents/MacOS/soffice` is absent. **Render/pixel diff skipped; no numeric pixel result.** Top remaining risks: absent item previews, text/font parity, metadata survival, and shared dependency edits. General OOXML coverage, real PowerPoint validity, and security budgets are not established by this probe.
