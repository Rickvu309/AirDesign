ISSUES

Reviewed all 51 screenshots, strategy boards, Copy Kit and decision notes. Later decisions take precedence; retired designs are not findings. State chains below cover F01–F15 and every supplied screen flow. Missing states are specification gaps, not claims about implemented behavior.

### F07 — Usage, resets and payments · S81.01, S91, S92, S99

States: available → limited → confirm → reset → resume; insufficient balance → amount → provider/open → paid/failed/expired/cancelled; paid → credits → pending reset, if still applicable.

- **HIGH — Delayed reset has no validity boundary.** F07: “the reset runs as soon as the payment lands”; also “One reset per limit hit.” Nothing says what happens when Monday resets usage before payment arrives, or another tab already resets it. A payment must still credit the wallet, but must not spend $5 on the obsolete request. **Smallest fix:** bind reset authorization to a usage generation/limit event; invalidate it on weekly or other successful reset. Recheck atomically when payment lands. Define cancellation of that authorization separately from cancellation of payment.
- **HIGH — Auto reset has no fallback or continuation rule.** F07 says “With auto reset on, $5 leaves the balance and nothing shows,” but also caps it at “up to 3 a week” and says runs stop at the limit. No transition covers insufficient credits, the fourth hit, enabling auto reset while already limited, or whether a successful auto reset continues the run. **Smallest fix:** specify these branches: eligible auto reset continues; no funds/cap reached stops at the current change and shows the same limit card. Define whether enabling it while limited authorizes an immediate reset.
- **HIGH — Open payment can block purchases indefinitely.** F07 maps “anything unknown stays open” and allows “One open payment per person.” No reconciliation trigger or resolution exists after a missing webhook, unknown provider status or failed Cancel. S91.02 only offers Open payment page/Cancel. **Smallest fix:** reconcile on return/reopen and after expiry; retain a resolving state until provider status is verified, with retry for failed cancellation. Never turn a merely delayed confirmation into S99 “Nothing was charged.”
- **MED — Payment results do not have a destination outside Settings.** S92.03 starts payment over the editor; S91.02 and all payment results exist only over Settings. F07 never defines what appears if payment lands after navigation, closure or sign-out, or how the person returns to the saved request. **Smallest fix:** deliver results against the signed-in account wherever it is open; restore wallet/history on return and retain a link to the waiting deck. Show reset completion only if a reset actually occurred; Resume stays explicit.
- **MED — The active board still specifies mutually exclusive components.** F07 says “limit card, not a popup,” then “one standard popup”; “only finished payments and resets,” then “money on the way shows in the popup and history”; “AirDesign never shows or stores ways to pay,” then “a row under Pay with.” These contradict the final pricing notes and S81/S91/S92. **Smallest fix:** remove those obsolete branches and the X6 saved-method path; use the inline card, waiting banner and amount-only dialog throughout.
- **MED — Amount changes without a transition.** S91.01 selects $10, previews $15 + $10 = $25; S91.02 waits for $25, and S91.03 credits $25 to reach $40. **Smallest fix:** keep the chosen amount through the sequence: either select $25 in S91.01 or change the next screens to a $10 payment and $25 balance.

### F03 — Edit and refine · S41, S42, S43, S49

States: grid ↔ slide; hover → hold → insertion; select → ask → working → complete/stopped/failed/limited; tool → apply/cancel → editor; undo/resume → editor/working.

- **HIGH — A second tab can silently steer the wrong request.** F03 permits “one Aira run per deck” and says a new message “joins the running run.” A second tab may not yet know a run exists; its apparently fresh request silently joins another task. The selection rule also says “the tab used last,” without distinguishing an explicit chat selection from external-agent context. **Smallest fix:** when submitting, return the authoritative active run and require the UI to present the message as steering that run; capture an explicit request's deck/selection at submission. Use last-active-tab context only for an external context lookup.
- **MED — User-agent run controls do not satisfy the shared promise.** F02 promises the person can “stop any run any time, from either agent”; F03 sends them to their own app. S42.03 has the working glow but only Aira's completed reply and Undo, with no route to stop or inspect the external run. The final no-label glow decision does not supply that route. **Smallest fix:** define one discoverable way to identify and stop/revoke the active external run, and associate its changes/undo with that run rather than Aira's previous reply.
- **MED — Tool actions have no target rules.** S43.07 offers Remove background and Boost resolution while only the slide is selected. S43.06 style rows do not say whether they insert text or restyle selected text. **Smallest fix:** define applicability and selected-object requirements; disable image actions without an image, and specify insertion versus restyling for text styles. No new screen is needed.

### F15 — Recovery · S29, S49, S69, S99

States: failure → quiet retry → reported failure → retry/resume/undo; offline → local queue → reconnect → reconcile → synced/conflict.

- **HIGH — Offline replay cannot always honor “the person's edits always land.”** F15 promises queued edits and latest-property-wins between tabs; Engine Constraints also check existence/parent/order and never reuse ids. If another tab deletes a slide, or F14 trashes the deck, offline edits reference absent/read-only objects. No reconciliation outcome preserves the queued work. S49.02 only says “Edits are saved on this device.” **Smallest fix:** distinguish recoverable property conflicts from structural/deletion conflicts; retain rejected edits locally, explain the conflict, and offer recovery into an owned active deck. Never silently discard them or resurrect trashed content.
- **MED — Failure snapshot contradicts its progress.** S49.01 says “Read 1 file, built slides 1 to 3,” yet slides 4, 5 and the Outlook stack already contain the completed deck's content. S42.01 correctly uses queued placeholders. **Smallest fix:** show the actual partial snapshot, or change the activity to explain that this was a later run on an existing deck.

### F04 — Export · S61, S69

States: options → fit review if flagged → build → download/failure → retry; running agent → export current snapshot/wait for run.

- **HIGH — Export skips required decisions.** F04 explicitly leaves “the flagged-items review state” undesigned, but requires Fix or Export anyway; it also requires a choice between exporting current changes and waiting for an active run. S61.01/.02 go straight from options to Export. **Smallest fix:** define these conditional states in the existing dialog, freeze the chosen version, and ensure its fit report matches the built file. Define what waiting does if the run stops, fails or reaches its usage limit.
- **MED — Background export has no recoverable ready state.** F04 says the person can keep working and “is told when it is ready”; S61 only has options and a “downloaded” toast. Navigation/tab closure during a build, repeated Export, and a completed file whose browser download did not start have no defined result. **Smallest fix:** retain the export operation/version/options and expose its ready download on return; retry S69 against that same operation snapshot.

### F01 — Sign in · S21, S22, S29

States: intent → email → email challenge → verified → intent; expired/wrong → resend → challenge; change email → email.

- **HIGH — Email-code sign-in is unreachable.** F01 requires “Click the link, or type the code”; S22.01 offers only mail-app links, resend and change email. No code entry or wrong-code state exists. **Smallest fix:** add code entry/verification and invalid/expired-code recovery to S22; keep the original intent through resend.
- **MED — Email verification can outlive agent approval.** F01 links last 15 minutes; F06 approval expires after 10. Verification at minute 12 succeeds, but the preserved connection intent is already expired. **Smallest fix:** detect the expired OAuth request after sign-in and route to restart connection, retaining the authenticated session. Reused links should also distinguish an already-authenticated session from a genuinely expired challenge.

### F06 — Connect own agent · S71, S81.02

States: setup → external OAuth → sign-in if needed → approval → allow/deny/expire → callback → connected; switch account → sign-in → approval.

- **HIGH — Consent omits the return destination required to identify the requester.** F06 says the name is “the agent's own claim” and requires showing where it sends the person back. Neither S71.01 nor S71.03 shows claude.ai or “this computer.” **Smallest fix:** show the validated callback destination on the shared consent component before Allow.
- **MED — Connected is a dead end if the handoff fails.** S71.02 only says “Taking you back to Claude,” without a fallback action; Codex has no defined successful/failed local handoff state. **Smallest fix:** specify callback success/failure and give a manual return/close instruction after success, or restart after a failed/expired exchange. Do not label the connection usable before token exchange succeeds.

### F14 — Manage decks · S31, S33

States: browse/search → open/rename/duplicate/trash; trash → undo/restore/confirm purge → active/purged.

- **MED — Rename, duplicate and delete have no specified user entry.** S31.02–.05 show deck cards/rows without an action menu; no supplied state exposes these actions. S33.01 demonstrates the delete outcome, not how to reach it. F14 provides no alternative gesture. **Smallest fix:** specify the card/row context menu and its actions, including rename submit/cancel and duplicate completion/failure.
- **MED — Empty Trash confirmation has no target snapshot.** S33.03 confirms “Delete 3 decks for good?” while another tab can restore/add decks or the purge job can run. **Smallest fix:** bind confirmation to the listed deck ids and recheck trash membership; never purge a restored deck or newly trashed deck that was not confirmed.

### F09 — Settings · S81

States: tabs → edit/save/cancel; agents → connection details → revoke; account → confirm deletion → closed.

- **HIGH — Connection revocation is not reachable from the supplied design.** F06 allows two computers to create separate connections; S81.02 aggregates Claude into one Connected/Manage row. F09 acknowledges “connection details” is not designed. There is no way to select and end one connection. Aira's on/off toggle also has no mid-run semantics. **Smallest fix:** make Manage list individual approvals/devices with last-used information and revoke actions; define whether turning Aira off stops a current run or blocks subsequent runs.
- **MED — Profile and deletion transitions remain undefined.** S81.03 exposes Edit and Delete account; F09 marks email-change and delete confirmation undesigned. Email change requires confirmation at both addresses, but pending/rejected/cancelled changes have no state. **Smallest fix:** specify those outcomes and the deletion confirmation, including credit loss and what happens to an open payment before the account closes.

### F05 — Import and paste · S32, S41.04

States: menu → file selection/cancel → importing → editor/failed; failed → choose file/remove; paste → validate → insert/failed → undo.

- **MED — Failure recovery loses the reason needed to fix the file.** F05 requires password removal and specific size/type reasons; S32.03 only says “Unable to import” and offers Choose another file/Remove. The later Home-only design does not remove the requirement to explain refusal. **Smallest fix:** put the actual reason on that card. Define Remove as removing the failed import job/card, since no valid deck was saved.
- **MED — Paste has only a success state.** F05 promises the same native/kept/flagged behavior as import, but S41.04 only shows “2 slides pasted” and Undo. Nothing defines rejected/unsupported clipboard content, partial failure or where this paste's report is retained. **Smallest fix:** specify atomic insertion, an inline failure with no deck changes, and access to the retained report for successful flagged content.

### F11 — Templates · S43.01–.02

States: choose → apply → undo; create/save → check → apply/set default; newer version → accept/keep current.

- **MED — One picker implies two different operations.** S43.01 opens from New slide, suggesting insertion. F11 calls it the entry for choosing a look applied to the existing deck. Save/set default are explicitly undesigned, so F08's own-style path cannot be completed by hand. **Smallest fix:** distinguish insert-slide mode from apply-template mode and define each click's target; specify save/default actions in Design and keep application one undoable step.

### F12 — Images and assets · S43.03, S43.07

States: upload/search → validate → library → place → crop/replace → editor; rejected/no results/storage full → recover.

- **MED — Upload-to-reuse/adjust chain is incomplete.** S43.03 only exposes stock search and Upload image; F12 explicitly leaves personal library, crop/focal point and alt text undesigned despite promising reuse and “Every image has alt text.” **Smallest fix:** define placement and adjustment transitions, a route back to owned uploads and alt-text editing, plus inline rejection/no-results states.

### F10 — Discovery · S11, S12

States: landing → pricing/guide/intent → F01 → F02/F05/F06.

- **MED — Two promised entry intents are absent; pricing contradicts itself.** F10 requires Import and Use my own agent before sign-in. S11.01 only offers Start free/Sign in/sample deck and has no agent guide route; its Pricing placeholder says “Free to start, Pro for teams,” contradicting S12.01 “No plan, no trial.” **Smallest fix:** expose the import/agent intents and guide destination and remove the obsolete Pro claim. S13 is already acknowledged as undesigned; do not leave the guide link without a destination.

### F02 — First deck · S31, S32.01, S42

States: New deck → blank editor → prompt → working → complete/stop/failure/limit; external agent → connection if needed → created deck link.

No additional independent finding beyond the missing code path (F01), external-run control (F03) and recovery/payment branches above. The blank-editor entry is described by F02 even though all editor examples use a populated deck.

### F08 — Next deck · S31, S42

States: return → new/copy → default template or Basic → agent → refine/export.

No additional independent finding. The missing default-template transition is recorded under F11; duplicate entry under F14. F08 says “last edited first” while F14 says “last opened first”: **LOW — smallest fix:** explicitly assign ordering to Recents versus All decks so opening an unchanged deck has predictable placement.

### F13 — Sharing

Retired → export through F04. No share-link screen remains in the supplied set; no independent finding.

### Fix list

1. Bind delayed paid resets to the still-valid usage generation; invalidate obsolete authorizations.
2. Complete auto-reset eligibility, fallback and run-continuation rules.
3. Resolve unknown/missing payment events and failed cancellation without blocking top-ups forever.
4. Preserve offline edits when structural changes or deck deletion prevent replay.
5. Add email-code entry and verification recovery.
6. Add export warning review and active-run snapshot/wait decisions.
7. Expose per-connection revocation and define Aira toggle behavior during a run.
8. Show validated return destinations before agent approval.
9. Prevent silent steering/selection changes across editor tabs.
10. Deliver payment/reset results and saved-request return paths outside Settings.
11. Remove obsolete popup, pending-history and payment-method branches from F07.
12. Make the S91 payment amount consistent throughout the sequence.
13. Define account deletion and email-change confirmation/pending outcomes.
14. Supply deck management entry actions and bind purge confirmation to deck ids.
15. Separate inserting a slide from applying/saving/defaulting a template.
