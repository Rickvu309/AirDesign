# An edit carries only the writes that change the deck, so a value set again makes no undo step and never lands over another writer's change

`changingWrites` in `packages/doom/src/changing-writes.ts` drops each write whose value the node already holds, judged in order and by value, and every write to a property the edit sets and then sets back. The editor client's `push` in `packages/live/src/doom-deck.ts` runs every person's writes through it and answers `unchanged` with no undo step and no row when nothing is left. `compileAgentEdit` runs every agent's writes, Aira's included, through it, after each change is applied on its own, so a value a person set during the run is still refused as `person`; `edit_deck` sends nothing and answers `unchanged` when no write is left. Undo, redo and run undo do not use it: a step typed back to where it began is still one step. A caller never needs its own empty or same-value guard before `push`. `packages/doom/src/changing-writes.test.ts`, `packages/live/src/doom-undo-unchanged.test.ts`, the agent cases in `packages/doom/src/agent-edit.test.ts`, the unchanged case in `packages/mcp/src/tools.test.ts`, the icon picked again in `tests/browser/editor-tools.spec.ts` and the resize dragged back in `tests/browser/editor-transform.spec.ts` fail when a write that changes nothing makes a step or reaches the server.
