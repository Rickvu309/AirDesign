# A connector end paints where its shape last was, whichever person, agent, tab, undo or replay takes the shape off the deck

`lineRoute` in `packages/doom/src/line-ends.ts` is the only place an end becomes a painted point, and paint, layout problems and export all read it through `resolveSlide`. A hidden shape, or a shape on another slide, keeps its attachment. A hidden child of an auto-layout frame paints at the place the flow would give it, and that place does not push its shown siblings. A sibling that was already hidden stays out of the flow when a frame or a sibling is hidden. Anything else the slide did not lay out paints from the stored boxes of the chain, a deleted shape from its own box, and never at the line's frame corner. `freeLineEnds` in `packages/doom/src/freed-line-ends.ts` reads each end after the batch. An end that still names the shape the batch took off the deck frees where it painted. It carries the point through the line frame's placement before and after the batch, so a frame that turns or moves along a row keeps the point still. An explicit point or attachment to a live shape stays as the batch wrote it. This also lets undo restore a free point in the same batch that removes the target, and lets redo restore the first delete's free point. An end the batch itself draws onto a shape off the deck after it, on a line it creates or moves, it frees at the point that end paints (`paintedEnds`), so an undo that moves a line back into its frame after another tab deleted the shape still paints the end at the shape's last place. The write carries no base, so the delete wins and the whole line write lands over what another tab wrote before it, as the last write wins in Figma. A batch that brings a line back onto the deck inside a frame or group, as an undo of the frame's delete after another tab deleted the shape, frees the line's dead end where the line last painted when the device passes that view (`last`, the undo step's view in `turn` in `packages/live/src/doom-deck.ts`). The rule reads what the writes did to the tree, not which gesture made them. A shape still on the deck, wherever it moved, keeps its attachment, and a line that is itself gone is left alone. Every edit that leaves a device runs it in one of two places. `pushEdit` in `packages/live/src/doom-deck.ts` runs it for gestures, text sessions, the filmstrip, undo, redo and run undo, with the measure the editor painted with (`measure` in `DoomOptions`, which `Editor` in `apps/web/src/editor/editor.tsx` keeps current). `compileAgentChange` (`packages/doom/src/agent-compile.ts`) runs it for each `airdesign_execute` change, and `undoRunTool` (`packages/agent/src/undo-tool.ts`) for `undo_run`, with the host's measure of the fonts of the deck before and after the batch, taken whenever the batch may take a layer off the deck (`mayLeaveDeck` in `packages/doom/src/freed-line-ends.ts`). The core never refuses a batch over a line end. After every batch, `landEdit` frees each end on a shape off the deck of a line the batch takes a shape from, writes a geometry or a parent to, or brings back onto the deck inside a frame (`freedInFold` in `packages/doom/src/lost-ends.ts`), where the shape's stored box paints through the stored boxes of its frames as the deck held them before the batch, as from a tab that never saw another tab attach the line, a geometry write that turns a shape into a line on a deleted shape, or a restored frame whose line names a shape deleted meanwhile. So an end is attached to a shape on the deck or free, never a deleted shape's id. `partSql` in `apps/api/src/doom/doom-deck.ts` loads every line that names a shape the batch deletes, through the endpoint indexes of migration 28, and the shapes the loaded lines and the written lines name; when the folded batch takes a shape off the deck by a move into a frame already off it, or brings a subtree back onto the deck, `editDoom` reads again with that shape's lines or the subtree's lines, so the server's partial fold frees as the whole deck (`specs/line-end-batches`), and saves every line the fold freed. A write that names a shape off the deck keeps the end the line already holds, if the line stays in its frame (`keepLiveEnds` in `packages/doom/src/apply-edit.ts`). `invert` and `invertRun` put back each end that still holds what the step wrote, even after another tab changed the other end (`lineEndsBack` in `packages/doom/src/line-ends-back.ts`), so undo restores the attachment. An undo or redo the deck refused is sent again with the same per-end rule against what the other tab wrote since the press, and freed again against the caught-up deck (`onStandingOnly` in `packages/live/src/turn-replay.ts`). A text session paints the last non-empty draft, which the deck does not hold yet: while the text is empty, `draftWrites` in `apps/web/src/editor/text-leave.ts` measures that draft's point once and places it in the frame as the preview lays it out (`freedEnds`), and leaving passes the draft's view to `push` as `seen`, so the end stays where the person saw it in both. A delete read before the other tab moved the shape frees where this tab painted it (`specs/line-ends`, `checks-line-ends.md`). `packages/doom/src/line-end-place.test.ts` and `packages/doom/src/freed-line-ends.test.ts` cover hiding, other slides, delete, frames, ungroup, unwrap, slide delete, measured widths, a frame moved by a row and a turned frame. `packages/doom/src/lost-ends.test.ts` covers the deck's freeing, a moved shape and frame, a deleted frame, an inverse batch that restores an end as it removes the target, a redo, a geometry write alone and a restored frame. `packages/doom/src/line-end-writes.test.ts` covers a write naming a deleted shape, per-end undo and run undo, and paint of an end a deck saved before this rule. `packages/live/src/doom-line-ends-tabs.test.ts` replays two tabs: a stale move, an undo that removes another tab's shape, an unseen attach, in a frame too, a delete read before a move, a late undo and a late redo. `tests/line-ends-replay.test.ts` drives every edge of the `line-ends` model. `apps/web/src/editor/line-end-gestures.test.ts` pushes emptying a text, delete, ungroup and slide delete through the deck with undo and redo, and the empty text preview, in an auto layout row too. `packages/agent/src/edit-tool.test.ts` runs `unwrap`, a removed font and slide delete through `airdesign_execute`, and `undo_run` of another run's shape. `apps/api/src/doom-deck-line-ends.test.ts` lands an attach, a stale write, an unseen attach inside a deleted frame, a delete read before a move, a move into a frame off the deck, a new line drawn onto a shape the same batch deletes, a geometry write alone onto a deleted shape and a restored frame through the server, and `apps/api/src/testing/line-end-batches-replay.test.ts` drives every edge of the `line-end-batches` model through Postgres. `tests/browser/editor-line-ends.spec.ts` deletes the shape from the keyboard and checks the saved end.
