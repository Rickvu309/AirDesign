# An undo never names a layer someone deleted since, so a step on it can never hold the steps below it

`invert` in `packages/doom/src/invert.ts` leaves out every write to a layer whose parent is `null` in the deck it undoes over, and every move into such a layer, unless the same undo puts that layer back (`onStandingLayers`). The deck refuses those writes as `missing`, and `turn` in `packages/live/src/doom-deck.ts` keeps a refused step on top, so one deleted layer used to make every later Ctrl+Z refused for good (verdict 1494-0ca0e9e, finding 5). A step with nothing left is taken off and answers `nothing`, as Figma does nothing for an undo of an edit to a layer someone else deleted, and the next press reaches the step below. `NeverStuck` in `specs/undo-steps/UndoSteps.tla` fails on the old rule in 50 states, `tests/undo-steps-replay.test.ts` fails 48 edges on the old `invert`, and `packages/doom/src/invert.test.ts`, `packages/live/src/doom-undo-deleted-layer.test.ts` and `tests/browser/doom-undo-deleted-layer.spec.ts` fail when a deleted layer holds an undo or a redo.
