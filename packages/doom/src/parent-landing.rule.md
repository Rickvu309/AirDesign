# A parent write lands on a deleted node only when its base is that node's parent rev, the delete

`parentLanding` in `packages/doom/src/parent-landing.ts` is the only judge. `staysDeleted` and `takesBackDelete` in `packages/doom/src/apply-edit.ts` call it when an edit lands, and `onTop` in `packages/doom/src/view-of.ts` calls it so a queued edit keeps a parent base that is not already the delete. A write with that base restores the node, including into a parent the same edit creates or a frame that is still deleted, and the node paints only once that frame is back. Every other parent write on the deleted node is dropped and the rest of the edit lands, except a write with no base whose parent is missing or deleted, which is still refused `missing`. `packages/doom/src/parent-landing.test.ts` is the table, the queued undo, the group and the frame, and the two-client interleaving. `packages/live/src/doom-undo-steps.test.ts` restores a deleted slide with the other tab's undo.
