# A tab that undoes before it has seen another tab's edit of the same layer lands nothing and says so; a two-tab browser spec waits until the tab that presses a key paints the other tab's edit

`doom-undo-stray-box.test.ts` has two tabs group a layer, one nudge it, and the other undo the group. Before it caught up, the server refuses the undo's box write as stale, names the layer and prop in a notice, and the group stays. After it caught up, the undo lands with no notice. That is the designed answer, so a browser spec that presses a key in a tab after the other tab's edit waits until both tabs paint the same layers: `tests/browser/editor-undo-deleted-layer.spec.ts` compares the painted box, or the order of `[data-node]`, in both tabs. A read of the saved deck on the server shows only that the edit landed, not that the second tab has it. Without the waits, three undo specs failed 1 to 3 runs in 8 under 32 busy CPU loops (`editor-undo-deleted-layer.spec.ts` at 401, 411 and 454).
