# A turn queued offline and refused keeps every step

`drain` in `doom-deck.ts` meets a refused undo or redo, whatever the content refusal, the same way, unless catching up cannot resolve it (`catchingUpResolves` in `turn-replay.ts`: `shape`, `limit`, `person`, `run-fenced` and `last-slide` set the turn aside with a notice, as does any refusal that is not about the edit's content). It catches up, then `onStandingOnly` keeps only the writes that would still land, as `turn` would online: it drops each write to a property another writer changed since the press, deck-level fields such as the name included (the `invert` ownership test: the step's own edits and this tab's turns are the tab's, anyone else's is not), then each write `onStandingLayers` drops. What is left is sent again under the same once. `onStandingLayers` may also add the box of a layer whose parent the undo puts back (`replanted`), so a trim is a change of content, not of length, and the step the press pushed takes the deck it lands on as its `before` and the written values as its `writes` (`steps` of `onStanding`): Redo then puts back the box the layer had when the undo landed, not the one the tab saw at the press, which sent a layer another tab nudged back by the nudge (`packages/live/src/doom-undo-stray-box.test.ts`, the group's undo pressed before the nudge arrived). A press queued behind a trimmed one was built from the untrimmed step, so `onStanding` builds it again, in queue order, from the step the trimmed press now is: `invert` against the deck the queue leaves it, with the same ownership test and `onStandingLayers`, and it is taken off quietly when the press it undoes is gone. Left as built, a redo behind a replanted undo wrote the box the layer had at the press over the other tab's nudge, because the replant's rev counted as the tab's own (`packages/live/src/turn-replay-queued.test.ts`). With nothing left, the replay takes the turn off quietly with the step that would put it back. `releaseBases` gives later writes the base of any write they depended on that the replay removed. The replay folds each retained edit once, yields between slices, and publishes only while its starting fold and queue are current. An agent run's undo, undone in flight, goes through the same `drain`.

Dropping the whole turn lost the step and the one below it (verdict 1507-1fb8aa5, finding 2). Keeping a write to a property the other tab wrote got the whole edit refused `stale`, so the card jumped back: a real title has the role `title`, the deck name follows it, and the other tab's delete writes that name (verdict 1567-08dae41). Trimming only after `missing` left the same jump for a rename or a retype, which are refused `stale` on the first send (verdict 1567-23481f5).

`NeverLosesAStep` and `NothingJumpsBack` in `specs/undo-offline/UndoOffline.tla` fail in 209 states on each old behaviour, `tests/undo-offline-replay.test.ts` fails 52 to 80 of 664 edges, and `turn-replay.test.ts` and `tests/browser/editor-offline-tabs.spec.ts` fail.
