# A browser run starts its preview server at its worktree's port and uses the port the server reports, so two worktrees on one machine never fail on a shared port

The start is `AIRDESIGN_PORT` or 4400 plus a hash of the worktree path (`startingPort`). The server, `tests/browser/font-preview.mjs`, binds with Vite's `strictPort: false`, which tries the next port each time a bind fails, so no probe sits between the check and the bind. It prints `airdesign preview port <n>`, `webServer.wait.stdout` in `playwright.config.ts` reads that line into `AIRDESIGN_PREVIEW_PORT` once, and `use.baseURL` and every worker and child process read that one variable. Nothing else computes a port. `scripts/preview-port.test.mjs` holds the start port with a dummy server and checks the next port serves, two servers started together take two ports, and the config names no fixed url. Proven with two real runs from two worktrees forced to the same start: both passed, on 4518 and 4519.
