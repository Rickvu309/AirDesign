# A test that reads a repo file by path runs when that file changes

`scripts/test-reads.mjs` scans each test file for the repo paths it reads: a quoted path or a run of joined segments that sits within three lines of a file-reading call, or that a `const` holds and a reading call uses, and a relative template path such as `` `../public/${name}` ``, which names its folder. The names must be tracked files, folders at least two levels deep outside `apps` and `packages` or inside the test's own app or package, or a file name with an extension, which keeps a deleted file linked. A name only passed as a sample, a test or spec file, and an import are no link. For a file a script test reads, `scripts/change-map.mjs` turns on the `scripts` part, and `pnpm prove` plans that test, so `pnpm gate` and the recheck in `pnpm land` run it. For a file a unit test reads, the map names that test file among its unit tests, so ci runs it and the gate runs it past its budget, as it runs a changed test. Vitest relates tests only through imports and never sees these reads. Write a test's paths so the scan sees them, relative to `import.meta.url` or from the repo root, and there is no list to keep (`scripts/test-reads.test.mjs`, which replays the size limits on AGENTS.md and ci.yml that PR 1036 missed and the feature map test that PRs 1661, 1664 and 1666 broke in ci after the gate passed)
