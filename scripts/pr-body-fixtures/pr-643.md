## What changes

Opening a slide from Grid view (click, Enter, or Open in its menu) now carries that slide's card into the canvas, and the Grid button carries the canvas back to the slide's card. It uses a view transition with the panel timing (280 ms, the `--ease-panel` curve), and the rest of the page cross-fades in 150 ms. Back in the grid, the slide that was open is focused and scrolled into view, so a person lands where they were, even at slide 50.

With reduced motion the view changes at once, with no transition. Browsers without view transitions also change at once.

The timing lives in `packages/theme` as three new roles, `--duration-micro`, `--duration-panel` and `--curve-panel`, with the same values as `--ease-micro` and `--ease-panel`, because a view transition's animation takes a duration and a curve separately. No token's value changes.

## Proof

- `tests/browser/slide-opening.spec.ts` (new file; `slide-grid.spec.ts` hit its size limit, so its deck helpers moved to `tests/browser/slide-grid-deck.ts` and both files share them), new test "opening a slide carries its card to the canvas, and the grid carries the canvas back to its card" (motion on). It wraps `document.startViewTransition` and records which element has the transition name before and after each transition, and how long the moving group runs. Opening the grid: canvas → slide 2's card, 280 ms. Clicking slide 1: slide 1's card → canvas, 280 ms. Exactly one named element on each side, so the browser never drops the transition for a duplicate name. Measured: pass.
- New test "with reduced motion the grid opens and closes with no transition, back on the slide that was open": on 50 slides, End then Enter opens slide 50; the Grid button brings the grid back with slide 50 focused and in view; `startViewTransition` was never called. Measured: pass.
- A journey on `doe-heat-pumps.pptx` with motion on, slowed with the DevTools animation rate, opened slide 7 from the grid. Playwright's screenshots show the page under the transition layer, not the layer itself, so the motion is proven by the recorded names and timings above rather than by an image.
