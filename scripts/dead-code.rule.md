# An ordinary word in a script does not keep a package export alive

`scripts/dead-code.mjs` roots an export when a script loads that package and a script reads the export: a property access, or a name destructured from `packageBuild`. A local, a string, or a property key is not a read. A `package.json` subpath such as `@airdesign/catalog/icon-names` is a real import. `scripts/dead-code.test.mjs` plants `const routed` and `{ routed: true }` beside a load that never reads `routed`, and imports `@airdesign/shapes/marks` from the web root.

`pnpm dead-code --copy` exits unsuccessfully and lists unread object properties and reads of missing keys in web copy modules and site copy modules. Copy-only tests are excluded. TypeScript property symbols identify dotted and bracketed reads in TypeScript and JavaScript. Relative `createRequire(import.meta.url)` calls for copy modules resolve to source modules during the check, and passing a whole object to another module or using a computed key conservatively keeps its entries. Site templates count property accesses on relative named imports. The test plants an unused site key and a web key read only by a copy test.
