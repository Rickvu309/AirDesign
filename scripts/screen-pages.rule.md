# A design screen draws the page a person sees, with sample data, never a copy of it

The `screen-pages` step (`scripts/screen-pages.mjs`) walks the imports the app reaches from `apps/web/src/main.tsx`, leaving out screens and tests, from each file's parse: imports, side-effect imports, re-exports and `import()` of a literal path, and reads every `apps/web/src/**/screens/*.tsx` and `*-screens.tsx` file. A screen may draw a module the app reaches, plain data (a `.ts` file whose own imports are reached or data), or a harness: a `.tsx` file that imports only those, defines no component of its own that it uses (a declaration that returns JSX, alone, in `memo` or `forwardRef`, or as an object's values, drawn as `<R />` or `<K.R />`, called, or passed as a JSX value; constants, types and imports written `import { type X }` are not components), and draws a page `App.tsx` routes to, as `editor-sample.tsx` draws `DoomEditor`. Anything else fails, and so does a component a screen defines and draws itself; file names count for nothing. The reads from before the check are listed in `scripts/screen-pages-known.json`: fix them, never add to them, and the step fails a listed read that is gone. `scripts/screen-pages.test.mjs` replays the editor screens before 6809df540, which drew the old `EditorShell` behind 16 editor states, and fails a dead wrapper, a mock in a `*-sample.tsx` file and a frame built from the app's parts. Barrels and imports by a computed path are left to the dead-code sweep's reachability tool.
