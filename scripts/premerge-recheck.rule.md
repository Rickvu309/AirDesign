# A pull request merges only after its exact head, merged with the newest main, passes the gate, so a clash with a commit main gained after ci ran shows before the merge

Right before `pnpm land` enters the merge queue, or merges a head itself when `main` has no queue, it fetches `origin/main`. When main has moved past the base the PR's ci tested, it merges main into the head as one commit in a scratch worktree, runs `pnpm gate --all` there, and stops on a failure with the failed steps and the main commits whose files the failure names. With no queue it merges with `gh pr merge --rebase --match-head-commit <head>`, never auto-merge (`scripts/premerge-recheck.mjs`, `premerge-recheck.test.mjs` replays pull request 970 against `2a7448aa0`, `land-recheck.test.mjs`)
