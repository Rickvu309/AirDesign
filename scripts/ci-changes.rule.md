# An opened or updated pull request runs the parts its diff reaches, and a reopened pull request selects every part

The `changes` job runs `scripts/change-map.mjs` through `.github/actions/ci-changes` on the pull request's own diff: GitHub's merge commit against its first parent, `HEAD^1`. A reopened pull request, a merge queue run and a push to `main` pass `--full`. Selecting every part on a reopened pull request gives a fresh run a chance to test the original failure. The check jobs are the ones `changes` keeps from `.github/actions/ci-changes/check-jobs.json`. Journeys and design-findings run unless `changes` said their part is `false`, so a missing answer runs them. `ci` fails when `changes` did not succeed, when a job was skipped and `changes` did not say its part is `false`, and when `changes` left out a check job whose part it did not say `false`. The source job runs only the unit test folders `changes` chose and runs the model check only when `changes` said so; the metrics that read the whole unit run are then left to `main`. The map includes the PDF job when its inputs change (`scripts/ci-changes.test.mjs`, `scripts/ci-parts.test.mjs`, `scripts/check-steps.test.mjs`, `scripts/metrics.test.mjs`)
