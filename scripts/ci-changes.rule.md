# A pull request runs only the ci parts its change can affect, and the queue and main run every part

The `changes` job runs `scripts/change-map.mjs` through `.github/actions/ci-changes` on the pull request's own diff: GitHub's merge commit against its first parent, `HEAD^1`. A merge queue run and a push to `main` pass `--full`. The check jobs are the ones `changes` keeps from its list; corpus, journeys and design-findings run unless `changes` said their part is `false`, so a missing answer runs them. `ci` fails when `changes` did not succeed, when a job was skipped and `changes` did not say its part is `false`, and when `changes` left out a check job whose part it did not say `false`. The source job runs only the unit test folders `changes` chose and runs the model check only when `changes` said so; the metrics that read the whole unit run are then left to `main`. The map decides `pptx` and `corpus` from their path list and browser reach (`scripts/ci-changes.test.mjs`, `scripts/ci-parts.test.mjs`, `scripts/check-steps.test.mjs`, `scripts/metrics.test.mjs`)
