# The race list holds one issue per test, and only races that are still live

`recordRace` in `scripts/race-issue.mjs` is the one way a race becomes an issue, for `pnpm land`, the fresh-run check and the red-main bot. An issue is keyed by the file and the test title, never the line (`raceKey`). An open issue for the test takes a comment. Otherwise it reads the closed `Race:` issues for the test and the pull requests that closed them (`closedByPullRequestsReferences`), and takes the merged one with the latest `mergedAt`: when the failing commit does not contain that pull request's merge commit, the failure predates the fix, so it comments on the closed issue and files nothing; when it does, the fix did not hold, so it reopens that issue with the new failure as a comment. It asks `git merge-base --is-ancestor` when the caller has git and the commit is local, else the GitHub compare API, and when neither can say it files nothing and says why. Only a test with no open issue and no issue closed by a merged pull request gets a new one. `scripts/race-issue.test.mjs` replays #1142, filed for a commit from before #1136 fixed #1126, and a failure on a commit that has the fix
