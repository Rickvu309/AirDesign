# A change runs every CI part it can affect, and a change the map cannot place runs everything

`scripts/change-map.mjs` turns a list of changed paths into the parts that must run: `source` with the unit test folders, `scripts`, `design`, `browser`, `journeys`, `pdf` and `model-check`. The graph is the workspace packages from `pnpm-workspace.yaml` and their manifests, plus the imports of every code file outside a package. A changed path reaches its package or file and everything that imports it. Docs run only `source` and `scripts`, whose checks read them, and so does any file a script test reads by path (`scripts/script-test-reads.rule.md`). The PDF job follows the inputs in `scripts/browser-change-map.rule.md`. `node scripts/change-map.mjs --paths <file> --jobs <json>` prints the answer as GitHub outputs, and the reason to the log. Any `package.json`, the lockfile, CI config, the check runner, shared test setup, a path no part owns, a diff that cannot be read, and `--full` run everything (`scripts/change-map.test.mjs`)

The red-main bot uses the failed job name to look up its part. An unread diff or unrecognized job name keeps the job in reach. The spec-sync command feeds a proof report and the script checks. A change to it selects source and scripts.
