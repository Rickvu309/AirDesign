# A full source run splits the unit test files across shards by their recorded seconds, and each file runs in exactly one shard

`tests/unit-seconds.json` holds each unit test file's seconds: its imports, setup and tests. `pnpm check --part=source --shard=<n>/<total>` hands Vitest `--shard`, and the sequencer in `scripts/vitest-longest-first.mjs` gives the heaviest file to the lightest shard with `weightedShares`, the split the browser shards use. A file with no record weighs the median. A local run of every unit test file that passes records a new file and rewrites one that moved past half or double its record. Shard 1 also runs every other step of the source part, so each of them runs once; a later shard runs only the unit tests and their metrics. A change that narrows the unit tests runs one source job with no shard. Each shard prints its own `known-failures`, and the whole run's number is their sum; only the shard that runs `apps/web/src/deck-paint.test.ts` prints `slides-repainted`. A later shard has no model check beside it, so a replay with no cached dump makes its own. `unit-shards.test.mjs`, `check-steps.test.mjs`, `change-map.test.mjs` and `metrics.test.mjs` hold the split
