# A full source run splits the unit test files across shards by their recorded seconds, and each file runs in exactly one shard

`tests/unit-seconds.json` holds each unit test file's seconds: its imports, setup and tests. `pnpm check --part=source --shard=<n>/<total>` runs only the unit tests and their metrics, hands Vitest `--shard`, and the sequencer in `scripts/vitest-longest-first.mjs` gives the heaviest file to the lightest shard with `weightedShares`, the split the browser shards use. A file with no record weighs the median. A local run of every unit test file that passes records a new file and rewrites one that moved past half or double its record. One source job with no shard and `unitTests` set to `[]` in `check-jobs.json` runs every other step of the part, so each runs once. A change that narrows the unit tests runs one source job with every step and no shard. Each shard prints its own `known-failures`, the first adds the repo's listed misses and browser faults, and the whole run's number is the sum of the shards; only the shard that runs `apps/web/src/deck-paint.test.ts` prints `slides-repainted`. `unit-shards.test.mjs`, `check-steps.test.mjs`, `change-map.test.mjs`, `ci-changes.test.mjs` and `metrics.test.mjs` hold the split
