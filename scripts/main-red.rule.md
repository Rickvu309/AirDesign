# A pull request's ci failure that is main's own failure never counts against it, and land never tells its agent to fix main's error

When ci fails on a pull request or the queue drops it, `pnpm land` reads the push runs of `ci` on main. Main counts as the cause when it was red when the run started and every failed job and test of the run, shard numbers aside, is one that main's red push runs failed in. Then land says `main is red since <commit>, not your change: <job>` and prints no advice to fix. It waits for a push run on main to pass, and names an open revert of the first red commit while it waits. Then it takes a run on the green main: it closes and reopens the PR, or queues it again, with a comment as the record. A failure that adds any test of its own stays the PR's (`scripts/main-red.mjs`; `main-red.test.mjs` and `land-main-red.test.mjs` replay runs 43643100126 and 43646212621 against main's run 43642103096)
