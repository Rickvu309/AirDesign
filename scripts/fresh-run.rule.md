# Land takes one fresh run for a test failure the pull request did not edit, and records a race only after that run passes the test

Evidence decides, not the change map. A failed test is owned only by the files it runs. A browser spec is owned by its own file and the helpers it imports, directly or through other helpers, found by reading `import` lines under `tests/` and `.agents/skills/verify-airdesign/`. A journey failure in `tests/journeys/journeys.spec.ts` is owned by that spec, the journey file named in the test title under `.agents/skills/verify-airdesign/journeys/`, and the helpers either imports. A change to a Playwright config owns every browser or journeys failure. A `design-states` failure is one state, read from the `"page"` field: it is owned only when the diff changes that state's file, `.agents/skills/verify-airdesign/look/states.mjs`, or the spec itself. Another browser spec, another journey, a rule file and the recorded-weight files `tests/browser/spec-seconds.json` and `tests/journeys/journey-seconds.json` own nothing, so a pull request that only adds a spec or a seconds row leaves another test's failure outside the diff. The race is titled `Race: design-states › <state>`, and a hand-filed title with a journey suffix is the same issue. Missing job logs, unread files and a failed step that is not a browser or journeys step stop too. Every other named browser, design or journeys failure takes one fresh run per head, even when the change map says the diff can affect the failed job: the map works at job scope, and nearly every app change reaches every browser job.

Land comments on the pull request that the failure is in tests it does not edit and that one fresh run will tell. It closes and reopens the pull request, or queues it again after a queue drop. The comment marks the head and the failed run. A reopen selects every ci part so the failed jobs run again. Land files a `Race:` issue only when the fresh run on the same head passes ci and executes the failed jobs successfully, so a test that fails and then passes on one head is the evidence. It names each recorded issue in its output. When the fresh run fails the same test again, land records nothing, says the test failed twice on this head so the change most likely causes it, and stops for a fix. A merge-queue run on a different commit cannot confirm a race on the pull request head. `ci` fails attempts after the first.

The red-main bot keeps the change-map verdict for a failure on `main`, through `byMap` (`scripts/red-main-revert.rule.md`).
