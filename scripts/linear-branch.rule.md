# A pull request branch holds no merge commit and no work-in-progress commit, because a rebase merge replays commit by commit: the merge queue drops a merge commit as `merge_conflict`, and with no queue GitHub refuses to rebase it

`pnpm land` rebuilds a branch that holds one as a single commit on the `origin/main` it just fetched, with the tree `git merge-tree --write-tree` gives for that main and the branch head, so no change is lost; it refuses instead when that merge conflicts or files are uncommitted, and prints the head it replaced. The `linear-branch` step of `pnpm gate` and `pnpm check` (`scripts/linear-branch.mjs`), and the pre-push hook, refuse a branch with a merge commit since `origin/main` and print `node scripts/linear-branch.mjs --rebuild` (`linear-branch.test.mjs`) A commit titled `wip`, `fixup!`, `squash!` or `amend!` is refused by the same step and hook, which print the rebuild command with `--message`, since 9b0587d26 and 7f6db26e5 reached main with WIP titles.
