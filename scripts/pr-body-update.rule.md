# A PR body is set only through `pnpm land --body-file` or `pnpm pr-body`, which run the body rules of `bar` first, never through a raw `gh api` PATCH

`pnpm pr-body <number> <file>` (`scripts/pr-body-update.mjs`) reads the PR's current head and changed files, runs `bodyFaults` through `pullBodyFaults` in `scripts/bar.mjs`, prints bar's own `Body:` lines and writes nothing when one fails, and PATCHes only a body that passes. It re-reads the head and base just before the PATCH and refuses, writing nothing, when either moved; it reads them again after the PATCH and fails when they moved. GitHub cannot condition the write on a head, so a push in the instant between the last read and the PATCH is the one window left, and the next `bar` run judges that body. `pnpm land --body-file` runs the same rules against the local branch before it pushes. `scripts/pr-body-update.test.mjs` replays a body that names an old head's hash and a visible change with no `## Before / after` (refused, nothing PATCHed) and a clean body (PATCHed); `scripts/land-bar-body.test.mjs` does the same for land, before the gate, edit and push, and `scripts/land-body.test.mjs` keeps land's attribution refusals; `scripts/bar-base.test.mjs` fails when `bar` does not name the command beside a body fault
