# A hover ends on the native pointerleave, never on React's onPointerLeave

`apps/web/.oxlintrc.json` fails a DOM element in `apps/web/src` that takes `onPointerLeave` or `onMouseLeave`. React builds its leave from the pointerout that the browser sends from the node under the pointer. When that node was just removed, as the text editor is on Escape, the browser sends no pointerout until it hovers the replacement on its next frame, so a pointer that leaves first gets no React leave and the hover stays on. The canvas then drew its frame's hover outline round both text rows after an undo (`frame-text-undone`, 3 of 5 sheet runs). `use-canvas-pointer.ts` listens for the native `pointerleave`, which the browser still sends to the stage. `tests/browser/doom-editor-select.spec.ts` holds the page between closing the editor and the pointer leaving, and fails without it.
