# A text action reads the selection the text editor holds now, never the last one it heard

The browser owns the text editor's selection and reports a change only through `selectionchange`, which it sends later, in a task of its own. So the text session's `anchor` and `focus` can trail the selection by a keystroke. Every session action that works on the selection (`mark`, `link`, `align`, `list`, `indent`) starts from `live()` in `use-text-session.ts`, which asks `text-host.tsx` for the selection at that moment. When focus moves out of the text, `text-host.tsx` records the selection on `focusout`, before the browser moves it into the next field. The Link field then linked 3 letters of 4 (`editor-text-link-range.spec.ts`, CI run 45315098330). The Link field commits through `text.link`, so it reads the same live selection. What the field shows still comes from the copy the canvas reports in an effect, `onWords`, which React runs before the next event.

`tests/browser/editor-text-link-range.spec.ts` and `tests/browser/editor-text-format.spec.ts` extend the selection and move focus or click in the same task, so the selection event arrives too late, and fail without this.
