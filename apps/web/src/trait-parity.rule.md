# An authorable trait field is live in every authoring layer or in none: its codec, its agent description and example, its control label, a read of it from the export, and a judged PowerPoint case

`pnpm typecheck` and the `build` step fail when a declared field has no entry in `traitXml`, `traitWire`, `traitControls` or the probes of `apps/web/src/trait-parity.test.ts`, using mapped trait/field types, or when an agent example is invalid. The parity test lands each field's example as an agent via `edit_deck`'s reader and as a person, exports it, reads it back, paints it, undoes it to the original bytes, wants a `scripts/pptx-cases` entry whose `covers` names it, and wants words for every label, description and option. Its `control` probe sends the example through the design panel's row, `planChange` and the person's queue. Its `inherit` probe sends `null` through the row of a field its trait declares `inheritable` and wants the inherited value in the export, and the copy probe wants that row's reset words. An alpha field has no row: the test sends `{ opacity: 60 }` as an agent and through the Opacity row to one element of each kind with an alpha field, and wants each such field to read 60 % in the export, paint, undo to the original bytes and be covered by a case. `apps/web/src/control-kinds.test.ts` wants a component and a `tests/browser/control-<kind>.spec.ts` for every control kind a field uses, inside a union, a record or a list too
