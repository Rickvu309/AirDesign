# What enforces each rule

A rule with a check fails `pnpm gate`, `pnpm check`, `pnpm check:pptx` or the merge. A rule marked review is a judgment call, and nothing fails when you skip it. When a mistake repeats, give its rule a check and move the row.

| Rule | Enforced by |
| --- | --- |
| No comments, no lint suppressions | lint: `no-comments` and the comment scan |
| No raw hex, color mix, sized arbitrary class or blanket transition | lint: `no-raw` |
| No file or folder named `utils`, `helpers` or `common` | lint: the name scan |
| One word per idea: a word listed in `tooling/oxlint-plugin-airdesign/glossary.json` is replaced by the word it names | lint: the name scan reads the glossary. A line kept on purpose is listed there with a reason. It warns for now and blocks nothing |
| Product code takes the clock, random ids and temp folders as options: no read of `Date.now`, `Date()`, `new Date()`, `performance.now`, `Temporal.Now`, `Math.random`, `crypto.randomUUID`, `crypto.getRandomValues`, `tmpdir` or `TMPDIR`, except as the `??` or default-parameter fallback of an option | lint: `no-hidden-input`. It warns for now and blocks nothing |
| Only `packages/document` makes an `ElementId`: no type assertion to `ElementId` outside `packages/document/src` | lint: `no-element-id-cast`. It warns for now and blocks nothing |
| A package exposes only its `index.ts`, declares what it imports, and stays pure | `pnpm check:boundaries` |
| A package's `index.ts` exports only names a caller outside the package, or a test through `index.ts`, uses | `scripts/interface-width.mjs`, the `interface-width` step of `pnpm check`. It warns for now and blocks nothing |
| A file an agent writes that is over 5,000 tokens does not grow, and no new file starts over it. A token is four bytes | `scripts/file-size.mjs`, the `file-size` step of `pnpm check`. Its message says how to split the file |
| No hand-kept list of what a folder holds: `pnpm typecheck` reads `apps/` and `packages/`, `pnpm test:tooling` reads `scripts/`, and the spec replay reads `specs/` | the `references` step of `pnpm check` fails when the root `tsconfig.json` lists references |
| Unit tests run with nothing built: a test reads sources, never a package's `dist` | `scripts/source-only.mjs` makes vitest refuse to load any `apps/*/dist` or `packages/*/dist` file, so a test that reads built output fails even when a build ran first. `scripts/source-only.test.mjs` fails when a vitest project drops it. `pnpm check` runs typecheck, build and site one after another beside the tests, because all three write `dist` |
| Two builds never run at once: each `tsc -b` writes the `dist` of every package it references, so two at once leave each other half-written declarations and fail with type errors the source does not have | `scripts/build-order.test.mjs` fails a `pnpm` command in `package.json` or a workflow that builds two projects with `--filter` and no `--workspace-concurrency=1`. The `journeys` build failed this way on main at a83f2535 |
| A state machine keeps its invariants | `pnpm check:specs` |
| Every spec in `specs/` is replayed against the code by a test, or listed with a reason | `scripts/spec-replays.mjs`, the `spec-replays` step of `pnpm check`. It warns for now and blocks nothing |
| A spec is checked again when the code it describes moves: `specs/<topic>/covers.json` names the declarations its model describes, with their digest at the last sync | `scripts/spec-sync.mjs`, the `spec-sync` step of `pnpm check`, names each spec whose covered declarations changed or went since its sync. `--sync <topic>` records a new sync only after `pnpm check:specs <topic>` passed. It warns for now and blocks nothing |
| A spec property the code breaks today is kept in `<Module>.known.cfg` beside an `it.fails` test | `pnpm check:specs` fails when a known config stops failing |
| An edit changes only its PowerPoint parts and adds no validator error | `pnpm check:pptx` |
| Every lint rule has a test and is switched on | `scripts/bug-rule.mjs` |
| Rule code in `tooling/` stays under 10 percent of product code | `scripts/bug-rule.mjs` |
| Remove clean, unused worktrees whose work is on `main` or whose upstream is gone; wait 12 idle hours for detached work or branches with no commits | `pnpm gate` and `pnpm check`: `scripts/worktrees.mjs` |
| Stashes are shared; recover only yours | `scripts/worktrees.mjs` warns on missing stash sources during `pnpm check`; read-only |
| A local branch with no worktree that holds nothing `main` lacks does not stay on the machine, and a clean main checkout follows `origin/main` | `pnpm gate` and `pnpm check` delete the branch and fast-forwards the checkout with `scripts/worktrees.mjs` |
| The branch of a pull request closed without merging does not stay on GitHub | the `closed-branch` workflow deletes it when the pull request closes. The pull request page can restore it. It leaves `main` and `archive/` branches alone |
| Staged files are formatted without staging a person's unstaged edits | `scripts/pre-commit.mjs`, installed beside `pre-push` by `scripts/install-hooks.mjs`; an unformatted partly staged file refuses the commit |
| Cheap deterministic failures do not wait in the check line | `scripts/check.mjs` runs its `preflight` steps before `takeMachineLock`; `scripts/check.test.mjs` proves a failure takes no lock. `pnpm gate` takes none |
| Run `pnpm gate` after your last edit, before every push; `pnpm land` runs it | `pnpm gate`, or a passing `pnpm check`, records the files it passed; the `pre-push` hook refuses any other commit and names `pnpm land` (`scripts/checked.test.mjs`) |
| The gate runs what the diff reaches and waits in no line | `scripts/gate.test.mjs`: cheap checks, changed packages and their dependents build, `pnpm prove --plan` tests; past 40 unit files only changed ones. ci runs every step |
| A commit whose test failed is not pushed; a failed test is load only when it passes alone | `pnpm gate` and `pnpm check` stamp no commit with a failed `test`; `pnpm land` stamps after the alone rerun (`scripts/land-check.mjs`) |
| Titles and PR bodies follow the rules above; a PR names its areas | `pnpm land` refuses a bad title before the gate and warns on a body with no `## Proof`; the `commit-titles` step warns; the `bar` check adds `long-title` and the area labels of `scripts/areas.json` |
| A PR is in the merge queue, not only believed to be | `pnpm land` reads the queue back and stops when the PR is neither queued nor armed (`scripts/merge-queue.mjs`) |
| A failed ci job is never rerun to pick up a fix that merged since | `pnpm land` has no rerun and prints whether `main` moved (`scripts/land-report.mjs`). A hand-run `gh run rerun` is caught only in review |
| A conflict with `main` is found before the gate; no conflict marker is committed | `pnpm land` runs `git merge-tree` first and scans the commit before the push; the `conflict-markers` step of `pnpm check` scans it too. The step warns for now and blocks nothing |
| A pull request targets `main` | the `bar` check fails on any other base and names `pnpm land` as the fix; `pnpm land` moves an open pull request's base to `main` before the push |
| A pull request's title, body and base change through `pnpm land`, never `gh pr edit`, which fails on this repo with the Projects (classic) error | `pnpm land --title` and `--body-file` set an open pull request's title and body through the REST endpoint (`scripts/pull-edit.mjs`). `scripts/land.test.mjs` fails when any line land prints tells the agent to run `gh pr edit` or `gh pr create` |
| A commit rebuilt from a stale tree does not undo other people's work: a branch does not put files back to content `main` has since replaced, unless its commit body says `Reverts: <path>` | `pnpm land` stops on it before the gate, and the `stale-tree` step of `pnpm check` runs it too (`scripts/stale-tree.mjs`). The step warns for now and blocks nothing |
| A migration number is used once | the `migration-numbers` step of `pnpm check` compares the record with `origin/main` and names the next free number. It warns for now and blocks nothing; `pnpm land` stops on it |
| A dropped queue entry is seen | `pnpm land --watch` exits 1 with the queue run's failed tests when the queue drops the PR |
| The local check queue keeps its rules | `CHECK-QUEUE.md` lists each rule of the machine lock and what holds it |
| A hung step cannot hold a check slot | `stepRunner` in `scripts/check.mjs` limits a local step (720 s for `test`, 480 s otherwise), kills its group and fails it naming the command; `runCheck` runs the rest. `scripts/check-hung.test.mjs` checks the slot is free. ci sets none |
| A local browser run uses at most 4 workers | `playwright.config.ts` sets the count through `workerLimit` in `tests/browser-workers.ts`, and the `globalSetup` in `tests/browser/launch.ts` stops a larger `--workers` with one line unless `AIRDESIGN_BROWSER_WORKERS` is set. ci is left to Playwright's default, two workers on its four cores: four made each test about 1.7 times slower for no clear gain |
| A ci job that runs the database tests, the PowerPoint check or the corpus gets PostgreSQL from the one action before it runs them | `scripts/ci-postgres.test.mjs` finds each job in `.github/workflows` that runs `pnpm check --part`, `pnpm check:pptx`, `pnpm check:pptx:corpus`, `pnpm test:journeys` or the mutation check, and fails when the job has no `./.github/actions/postgres` step before it |
| A ci job that replays the TLA+ specs gets the TLA+ tools from the one action before it runs them | `scripts/ci-tla.test.mjs` finds each job in `.github/workflows` that runs `pnpm check --part` or the mutation check, and fails when the job has no `./.github/actions/tla` step before it, when a workflow downloads the jar itself, or when the action's cache key or hash differs from the jar `scripts/check-specs.mjs` accepts |
| A test file sees only the rows it wrote | `postgresInfo` in `apps/api/src/harness.ts` gives each `apps/api` test file its own database, cloned from the template the globalSetup prepares; `scripts/vitest-api-database.mjs` drops it after each file, so the next file in a shared worker gets a new one, and `isolation.test.ts` fails when it sees another file's rows |
| A unit test file shares a worker only when nothing in it mocks a module or writes a global, and it never sees a global an earlier file in that worker left | `scripts/test-isolation.mjs` parses each file and isolates the rest; the shared, render-shared and api-shared projects' `scripts/vitest-kept-globals.mjs` puts `globalThis` back after every file, which `scripts/kept-globals.test.mjs` and `scripts/test-isolation.test.mjs` check. The render projects set React's act flag once in `scripts/vitest-act-environment.mjs`, so a render test does not write it |
| A trait's stored fields never change without a higher stamp, so the stored format rises and an older tab reloads before it reads a row it cannot | `packages/document/src/trait-format.test.ts` hashes each trait's fields against its stamp and keeps every shape a stamp ever had, so a changed field names the version to write |
| No stored register holds PR 478's `slide: "background"` command, and none of its colours is lost | `apps/api/src/background-rewrite.test.ts` runs setup twice from migration 13 on registers stored in that shape and wants fill rows on `<slide>.slide`, each clone opening with what its source showed, and nothing left. From migration 14 with `deck.background_backup` filled, it wants setup to drop the backup and change no deck, and the schema to match a fresh database's. `packages/live/src/cache.slide.test.ts` wants a command an older build left in IndexedDB or the unsaved journal shown and sent as a fill row. `packages/catalog/src/slide-wire.test.ts` wants the commit route to refuse it |
| A trait field is live in every layer or in none: its codec, its agent description and example, its control label, a read of it from the export, and a judged PowerPoint case | `pnpm typecheck` and the `build` step fail when a declared field has no entry in `traitXml`, `traitWire`, `traitControls` or the probes of `apps/web/src/trait-parity.test.ts`, which are mapped types over every trait and field, or when an example is not in the field's agent form. The parity test lands each field's example as an agent through `edit_deck`'s reader and as a person, exports it, reads it back, paints it, undoes it to the original bytes, wants a `scripts/pptx-cases` entry whose `covers` names it, and wants words for every label, description and option. Its `control` step sends the example through the design panel's own row, `planChange` and the person's queue, so a control that changes nothing fails. Its `inherit` step sends `null` through the row of a field its trait declares `inheritable` and wants the export to show the inherited value, and the copy step wants that row's reset words. An alpha field has no row of its own: the test sends `{ opacity: 60 }` as an agent and through the Opacity row to one element of each kind that takes an alpha field, and wants every alpha field that kind takes to read 60 % in the export, to paint, to undo to the original bytes and to be covered by a case. `apps/web/src/control-kinds.test.ts` wants a component and a `tests/browser/control-<kind>.spec.ts` for every control kind a field uses, inside a union, a record or a list too |
| Every control kind a trait field uses has one component and one browser test | `apps/web/src/control-kinds.test.ts` maps every declared field and text input to its control kind and fails when the kind has no entry in `controlViews` or no `tests/browser/control-<kind>.spec.ts` |
| Every gesture in the editor has one row in the gesture table and a browser test | `apps/web/src/gesture-coverage.test.ts` reads every `tests/browser/*.spec.ts` and fails for each row of `gestures` in `packages/render/src/gestures.ts` that no `covers(...)` call names, and for a `covers(...)` id that is not a row. `packages/render/src/gestures.test.ts` fails when a press of one row reads as another row where both work |
| A shipped migration is never edited; a change is a new migration | `apps/api/src/frozen-migrations.test.ts` checks each migration's exact sql against `apps/api/src/frozen-migrations.json`, and `scripts/frozen-migrations.mjs` only appends |
| Tests never retry | the Vitest and Playwright configs set no retries. A retry on one test is caught only in review |
| `main` takes only a commit that passed `ci` on top of the latest `main` | branch protection and the merge queue |
| The browser tests run in three shards on ci, each on its own runner, and the first shard runs both design scans `design-findings` judges | `pnpm check --part=side --shard=<n>/3` passes the shard to Playwright and runs the other side steps only in the first shard. `scripts/ci-parts.test.mjs` holds the three jobs and lists the first shard's tests to find `design-states.spec.ts` and `every-screen.spec.ts` there; `scripts/check.test.mjs` holds the steps of each shard |
| The browser tests judge a commit once on its way to `main` | the merge queue moves `main` to the exact commit its ci run passed, so the push run on `main` skips the side part when a merge-queue ci run passed that commit; `scripts/ci-parts.test.mjs` holds the condition. The main and pptx parts still run there, because only a run on `main` saves the caches every PR restores |
| The corpus check and paint fidelity judge a commit before it reaches `main` | the `corpus` job runs in the merge queue as well as on `main`, and the `ci` job fails unless it passed or was skipped, which it is on a pull request. Only a run on `main` opens the `main is red` issue (`scripts/ci-parts.test.mjs`) |
| The journeys judge a commit before it reaches `main` | the `journeys` job in `ci` calls `.github/workflows/journeys.yml` in the merge queue, and the `ci` job fails unless it passed or was skipped, which it is on a pull request and on `main`. Only a failure on `main` opens the `journey failed on main` issue (`scripts/ci-parts.test.mjs`) |
| Production passes the journey after every deploy | `production-journey.yml` runs after each successful `deploy` run. It first waits up to 15 minutes until the API's `/version` serves the deployed commit or a newer one that contains it (`scripts/production-commit.mjs`), and opens or comments on the `production journey failed` issue when it fails (`scripts/deploy.test.mjs`) |
| A metric that moves away from its goal, and a changed PowerPoint case or deck that was already judged, is seen by the owner | the `bar` check labels the PR `lowers-the-bar`. It does not block |
| Planted faults on changed code are reported | the `mutation` job, which warns about survivors and blocks nothing. Stryker leaves every symlink git tracks out of its sandbox (`linkedPaths` in `scripts/check-mutation.mjs`), and a crash fails the job while a run that hits its time limit only warns (`scripts/ci-crashes.test.mjs`) |
| The paint-fidelity count covers the corpus it names | `scripts/paint-fidelity-run.mjs` fails the corpus job when it crashes, judges no deck, skips a deck, stops at its time limit, or counts fewer matching slides than `metrics.json` records (`fidelityFailure` in `scripts/paint-fidelity.mjs`). A higher count prints a `record` line, and `scripts/ci-crashes.test.mjs` keeps that step free of `continue-on-error`. Its count goes in `metrics.json` as `paint-fidelity` |
| Local check time and CI wall time are told apart | `scripts/gate.mjs` times `gate-duration` in seconds; `scripts/check.mjs` times local `check-duration` in seconds. `ci-duration` times the merge queue in minutes in the `ci` job summary and warns over its limit (`scripts/ci-parts.test.mjs`) |
| A PR that changes what a person sees has a Before / after section with an image from the `proof` release | the `bar` check labels the PR `needs-before-after` (`scripts/before-after.mjs`). It does not block. It reads paths only: a `.ts` file in `apps/web/src` outside `copy/`, `apps/web/public` and server words are missed |
| An agent's comment or review on a pull request or issue starts with the agent line | review |
| A change to what `ci` checks is seen by the owner | the `bar` check labels the PR `changes-ci`. It does not block |
| A bug you find and do not fix is an `it.fails` test. A skipped, todo, expected-failure or no-expect test counts as a known failure | `scripts/metrics.mjs` prints the count on every run. A known failure is shown, never blocked. A deleted test is caught only by the `mutation` job, which reports the planted faults that tests no longer catch |
| A new check starts in `warnSteps` in `scripts/check.mjs` and blocks only after it has caught a real fault with no false stop | review |
| Extend before you build a parallel version, reduced motion shows the finished state | review |
| Tests take product words from `apps/web/src/copy`; existing duplicate literals are counted and additions per file and value fail with the export to import | `scripts/copy-literals.mjs`, the `copy-literals` step of `pnpm check`, covers browser tests, journeys and verify-airdesign journeys and look states |
| Copy: `better-writing`, `GLOSSARY.md`, current behavior | review; `no-limit-in-copy`: use `@airdesign/document` limits |
| How agents work here | review |
| Every design screen and named state of the app shows no mechanical design fault: cut, covered or invisible text and controls, internal names, empty panels, stacked frames, low contrast | the `design-findings` step counts what the scanner finds in the browser tests into the `design-findings` metric. It warns for now and blocks nothing. Looking at the images is review |
